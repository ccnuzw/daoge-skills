# 版本进入开发门禁

一个版本从“规划”进入“可以交给研发或 AI 实现”之前，必须满足下列条件。检查时逐项给出证据位置，不能只打勾。

| # | 门禁项 | 通过标准 | 自动检查 |
| --- | --- | --- | --- |
| G01 | 范围冻结 | 版本总览写清做 / 不做，并有去向说明 | - |
| G02 | 稳定编号 | 需求编号文档覆盖全部功能，无重复编号 | check-docs：ID001、ID002 |
| G03 | 功能主文档 | 每个功能都有主文档，规格状态为 Ready | check-docs：ST003 |
| G04 | 验收标准 | 每个功能有 Given/When/Then 形式的 AC | check-docs：AC001、AC003 |
| G05 | 测试设计 | 每个 AC 有测试层级、目标资产、目标命令 | check-docs：AC004～AC006 |
| G06 | 高风险设计 | 高风险功能有独立技术设计，分支 ID 全部可追踪 | check-docs：TD001、BR001、BR002 |
| G07 | 接口契约 | 公开接口在接口契约中登记，错误码有统一来源 | - |
| G08 | 数据模型 | 核心表有所有者功能和约束说明 | - |
| G09 | 冲突决策 | 已知冲突都有冻结决策，状态为“已冻结” | check-docs：DC001、REF002 |
| G10 | 追踪矩阵 | 功能 → 接口 / 数据 / E2E 映射完整 | - |
| G11 | 实现状态表 | 版本实现状态表已列出全部功能 | check-docs：ST001、ST006 |
| G12 | 链接有效 | 文档间链接与锚点全部有效 | check-docs：LNK001、LNK002 |
