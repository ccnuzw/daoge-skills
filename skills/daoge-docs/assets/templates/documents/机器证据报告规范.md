# 机器可读证据报告规范

本文只定义交付证据的机器契约，不保存产品、功能或架构结论。项目事实仍由对应权威文档维护。

## 报告类型

| 类型 | 必须证明 | `details` 核心字段 |
| --- | --- | --- |
| `development` | 干净检出、锁定依赖、构建、静态检查、单元和集成测试 | `clean_checkout`、`dependency_mode`、`services`、`required_checks` |
| `e2e` | 发布级环境中的逐用例结果，关键用例无失败或跳过 | `dependency_mode`、`required_case_ids`、`cases` |
| `performance` | 已批准负载与实际阈值比较结果 | `load_profile_id`、`load_profile_digest`、`approved_by`、`approved_at`、`scenarios` |
| `release` | 精确制品、迁移、备份、恢复、安全、冒烟、观察和回滚 | `artifact_digest`、报告指针及七类结构化检查项 |

使用 `new-evidence` 创建报告时，初始结果必须为 `not_run`。工具不会代替执行者填写通过结果。

## 公共字段

每份报告必须包含：

```text
schema_version
type
version
environment
commit
build_id
executed_at
result
commands[]
checks[]
artifacts[]
residual_risks[]
approval
details
```

时间必须使用带时区的 ISO-8601。摘要必须使用 `sha256:<64 位十六进制>`。报告不得使用个人临时文件作为唯一证据入口。

## 提交与构建绑定

四类当前报告必须绑定同一版本、同一 Git commit 和同一不可变 `build_id`。仓库存在 Git HEAD 时，报告 commit 必须与当前 HEAD 一致；允许使用不少于 7 位且能唯一匹配 HEAD 的前缀。

发布报告的 `artifact_digest` 标识实际待发布制品，不得只写标签或可变镜像名。`e2e_report` 与 `performance_report` 必须等于当前证据清单选择的报告路径。

## 命令和检查项

`commands[]` 记录实际命令、退出码和可选输出摘要。Release 门禁只接受退出码为 0 的命令。

`checks[]` 使用稳定检查 ID；声明为当前报告结论的检查项必须为 `passed`。`development` 必须包含 `build`、`static`、`unit`、`integration`。E2E 必需用例必须逐项存在且为 `passed`。

性能场景必须记录 `metric`、`operator`、`threshold`、`actual`、`unit`、`result` 和证据。检查器重新执行 `lte`、`gte`、`lt`、`gt` 或 `eq`，不信任手填的结果。

## 环境等级

| 环境 | 可以证明 | 不可替代 |
| --- | --- | --- |
| `local` / `local-mock` | 本地规则、构建和受控依赖行为 | staging 或生产依赖 |
| `integration` | 组件和数据库契约 | 完整用户旅程 |
| `staging` | 类生产拓扑的 E2E 与性能 | 生产批准 |
| `production-gate` | 发布前真实边界和演练 | 发布后的持续安全 |
| `production` | 已发布环境观察结果 | 下一次发布证据 |

E2E 和 Release 报告只接受 `staging`、`production-gate` 或 `production`。

## 审批和时效

最终发布审批必须填写：

```text
proposal_id
confirmed_by
confirmed_at
authority_digest
```

先运行 `python3 .daoge-docs/daoge_docs.py authority-digest --root .` 获取待审提案的权威文档摘要。确认时间必须晚于四类报告执行时间。任何纳入摘要的权威文档发生变化后，旧审批自动失效。

性能负载模型也必须记录批准人、批准时间和负载模型摘要；批准必须早于性能执行。

## 隐私与保留

- 不记录密钥、Token、签名 URL、完整敏感请求或未脱敏数据。
- 原始日志、截图和查询结果必须脱敏并使用受控存储。
- 证据保留时间服从安全、财务和合规要求；没有项目规则时由发布决策明确。
- `artifacts[]` 只保存稳定路径或受控存储引用。

## 失败不可覆盖原则

每次执行创建独立报告。失败、阻塞、环境无效和跳过批次必须保留，后续成功批次不得覆盖原文件。

当前证据清单只选择本次门禁使用的四份报告，不删除历史。Release 检查项只能为 `passed` 或有明确原因的 `not_applicable`；`not_run`、`failed` 和 `blocked` 必须阻止发布。
