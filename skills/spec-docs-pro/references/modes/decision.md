# 模式：冻结决策与 ADR

适用：字段、枚举、错误码、状态机、删除策略、幂等、并发、资金口径等出现冲突或待定（硬规则 4）；或需要记录有长期架构影响的选择。

## 冻结决策还是 ADR

| 场景 | 记录 |
| --- | --- |
| 统一某个业务口径或规格冲突（例如“删除是软删除”） | 冻结决策 `D{NNN}` |
| 有长期架构影响、需要记录备选方案和后果（例如“选 PostgreSQL”） | ADR，同时在冻结决策中记一条结论并引用 ADR |

## 步骤

1. **说清冲突。** 写明冲突出现在哪些文档或代码中、各自说了什么。
2. **给方案。** 2～3 个方案，每个写优点和代价，给出你的推荐。用户选择后再写入；用户授权你决定时，写明“由助手选定，用户授权”。
3. **写入。** 冻结决策追加到 `06-决策记录/V{n}-冻结决策.md`，格式按 `assets/templates/frozen-decisions.md`；编号取全项目最大值 + 1。ADR 复制 `assets/templates/adr.md` 到 `06-决策记录/ADR/{NNNN}-{标题}.md`。
4. **同步影响范围。** 逐个更新受影响的功能主文档（规则、AC、来源与追踪中引用编号）、接口契约、数据模型。需要改代码时列出改动点，但不在本模式内改代码，除非用户要求。
5. **取代旧决策。** 旧决策状态改为“已取代（由 D{NNN} 取代）”，内容保留不删。ADR 同理改为 `Superseded by ADR-{NNNN}`。
6. **校验。** `check-docs.mjs --only ID004,REF002,DC001` 检查编号重复和悬空引用。

## 输出

决策条目全文、更新过的文件清单、尚未同步的影响项（如代码）。
