# 状态词表与编号规则

本文件是状态词和编号格式的唯一定义。模板、检查脚本（`scripts/lib/status.mjs`）和文档浏览器都以这里为准。

## 目录

1. 四套状态，各管一件事
2. 实现状态
3. 规格状态
4. 证据状态
5. 决策状态
6. 编号格式
7. 文件命名
8. 旧文档迁移对照

## 1. 四套状态，各管一件事

| 状态类型 | 回答的问题 | 唯一记录位置 |
| --- | --- | --- |
| 实现状态 | 这个功能做到哪一步了 | `02-产品与版本/当前版本/V{n}-实现状态.md` 的“状态”列 |
| 规格状态 | 这份规格能不能拿去开发 | 功能主文档 frontmatter `spec_status` 和功能卡“规格状态” |
| 证据状态 | 这条 AC 的测试证据到什么级别 | 功能主文档“AC 逐项测试设计”表的“证据状态”列 |
| 决策状态 | 这条决策是否生效 | 冻结决策条目的“状态”行；ADR 的“状态”行 |

功能主文档里不写实现状态（不写 frontmatter `status:`，功能卡不写“状态”行），只链接到实现状态表。原因：同一事实出现在两处就会漂移，实现状态表是团队和浏览器共同读取的位置。

## 2. 实现状态

| 状态 | 进入条件 |
| --- | --- |
| 规划中 | 规格已登记，没有代码 |
| 开发中 | 有代码，AC 未全部通过 |
| 本地验证 | 全部 AC 在本地或 CI 自动化通过 |
| 待验收 | 预发环境证据齐备，等待业务验收 |
| 已完成 | 发布门禁或生产证据齐备 |
| 阻塞 | 写明阻塞原因和解除条件 |
| 已废弃 | 有对应决策；编号保留不复用 |

## 3. 规格状态

| 状态 | 含义 |
| --- | --- |
| Draft | 起草中，不能作为编码输入 |
| Ready | 需求、接口、数据、AC 已冻结，可以开发 |
| Deprecated | 功能废弃，文档保留供追溯 |

## 4. 证据状态

证据只能按真实级别记录，不能升格。

| 级别 | 含义 |
| --- | --- |
| 未创建 | 测试资产还不存在 |
| 已创建 | 测试文件存在，用例未补全或未运行 |
| 静态核验 | 只做了文档或代码审阅，没有运行测试 |
| 本地通过 | 本地或 CI 运行通过（含 mock） |
| 预发通过 | 预发 / 集成环境用真实依赖通过 |
| 生产通过 | 生产环境或发布门禁证据 |
| 失败 | 最近一次运行失败 |
| 不适用 | 写明理由 |

## 5. 决策状态

| 冻结决策 | ADR | 含义 |
| --- | --- | --- |
| 草案 | Proposed | 方案已提出，尚未生效 |
| 已冻结 | Accepted | 生效，作为开发和验收依据 |
| 已取代（由 D0NN 取代） | Superseded by ADR-NNNN | 被新决策替代，原文保留 |
| 已撤销 | Deprecated | 不再生效 |

## 6. 编号格式

| 对象 | 格式 | 说明 |
| --- | --- | --- |
| 功能需求 | `V{n}-FR-NNN` | 三位数字，版本内唯一 |
| 非功能需求 | `V{n}-NFR-NNN` | |
| 发布门禁 | `V{n}-RG-NNN` | |
| 跨功能验收 | `V{n}-E2E-NN` | 两位数字；旧写法 `E2E01` 可作为显示名：`V1-E2E-01 (E2E01)` |
| 功能内验收 | `ACNN` | 功能内唯一；跨文档引用写 `V1-FR-005/AC03` |
| 设计分支 | `B{功能号}-NN` | 功能号取 `V{n}-FR-NNN` 的数值，补足两位：功能 5 → `B05-03` |
| 冻结决策 | `DNNN` | 项目内递增，跨版本不复用 |
| 架构决策 | `ADR-NNNN` | 四位数字，文件名 `NNNN-标题.md` |

所有编号一旦分配：不改变、不复用、不重排。删除或废弃的编号登记在需求编号文档的“已废弃编号”表。

## 7. 文件命名

| 文档 | 路径 |
| --- | --- |
| 功能主文档 | `03-功能规格/V{n}/{NN-领域}/{NN}-{功能名}.md`，`NN` 与功能编号后两位一致 |
| 技术设计 | 与主文档同目录：`{NN}-{功能名}-技术设计.md` |
| 实现状态 | `02-产品与版本/当前版本/V{n}-实现状态.md` |
| 冻结决策 | `06-决策记录/V{n}-冻结决策.md` |
| ADR | `06-决策记录/ADR/{NNNN}-{标题}.md` |
| 后续版本规划 | `02-产品与版本/后续版本/V{n}-{主题}.md` |
| E2E 规范 | `05-测试与发布/端到端验收/V{n}-E2E-{NN}-{场景}.md` 或汇总在 `V{n}-端到端验收规范.md` |

## 8. 旧文档迁移对照

`check-docs.mjs` 会对非标准状态给出建议。常见映射：

| 旧写法 | 标准写法 |
| --- | --- |
| 设计中、未开始、Planned | 规划中 |
| 基础实现、进行中、部分实现、Implementing | 开发中 |
| Local Verified、本地通过（作为实现状态） | 本地验证 |
| 已通过（作为证据状态） | 本地通过（或按真实环境写预发 / 生产通过） |
| Production Verified、已上线 | 已完成 |
| frontmatter `status: 基础实现` | 删除，改写实现状态表；规格状态写 `spec_status: Ready` |
