# {{项目名}} 统一错误码

## 1. 文档目标

为所有对外接口提供稳定、可追踪、可本地化的错误口径；代码与测试引用 `error_key`，用户提示由前端按 key 映射。

## 2. 总体原则

### 2.1 双码体系

| 编码 | 用途 | 稳定性 |
| --- | --- | --- |
| 数值码 | 日志、监控、调用方判断 | 分配后不复用 |
| error_key | 代码、测试、文案映射 | 分配后不改名 |

### 2.2 数字错误码格式

```text
<3 位业务域编号><4 位序号>
```

示例：`1010001` = 业务域 101 + 序号 0001。业务域编号一次分配到位，新增模块追加新域段，不挪用旧段。

### 2.3 成功码

成功统一为 `code = 0`，不单独分配成功码。

### 2.4 稳定性规则

- 错误码不复用、不改语义；废弃码保留并标注替代项。
- 原始异常、SQL、堆栈不得直接暴露；统一转换为业务错误。
- 同一失败原因只能有一个 key，避免同义错误码扩散。

## 3. 统一响应格式

```json
{
  "code": 1010001,
  "error_key": "<domain>.<reason>",
  "message": "<面向用户的安全描述>",
  "request_id": "req_x"
}
```

若存在对外的兼容协议入口（如第三方 API 兼容层），错误外形按对应协议返回，但必须同时携带平台 `error_key` 与 `request_id`。

## 4. 业务域与模块编号

| 域编号 | 业务域 | 负责范围 |
| --- | --- | --- |
| 101 | <域> | <范围> |

## 5. 必备错误码

### 5.1 <业务域>

| 数值码 | error_key | HTTP | 触发条件 | 提示 | 负责功能 |
| --- | --- | --- | --- | --- | --- |

## 6. 维护规则

1. 新增错误码先登记本表，再写后端映射、前端提示与错误测试。
2. 错误码变化时同步功能错误矩阵与追踪矩阵。
3. 数值码与 error_key 一一对应；出现映射为空或一对多即为结构错误。
