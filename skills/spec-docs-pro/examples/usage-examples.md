## 示例 2：创建功能规格文档

### 场景

你需要为 CloudGate 项目添加"用户 API Key 管理"功能。

### 操作

```
使用 spec-docs-pro 创建功能规格：
- 版本：V1
- 功能名称：API Key 生命周期管理
- 领域：身份与权限
- 功能目标：让用户可以创建、查看、启用、禁用和删除 API Key
- 包含范围：
  - 创建 API Key（带名称、过期时间）
  - 列出所有 API Key
  - 查看单个 API Key 详情
  - 启用/禁用 API Key
  - 删除 API Key
- 不包含范围：
  - Key 权限继承
  - Key 自动轮转
  - IP 白名单
- 上游依赖：功能 02 用户登录
- 下游影响：网关鉴权、用量统计
- 风险评估：涉及密钥存储和管理，属于高风险功能
```

### 预期输出

Agent 会创建两个文件：

1. **`docs/03-功能规格/V1/01-身份与权限/05-API-Key生命周期管理.md`**

包含完整章节：
- 功能卡（编号 V1-FR-005）
- 目标与边界
- 需求说明（用户故事、页面交互、字段规则）
- 接口契约（5 个接口的完整定义）
- 数据与事务（api_keys 表设计）
- 验收标准（AC01～AC10）
- 实现与验证（工程落点和测试映射）

2. **`docs/03-功能规格/V1/01-身份与权限/05-API-Key生命周期管理-技术设计.md`**

包含高风险功能的详细设计：
- 风险评估（密钥泄露、未授权访问）
- 核心函数签名
- 密钥生成和存储策略（前缀明文、哈希存储）
- 伪代码实现
- 分支追踪（B05-01 到 B05-10）
- 并发控制
- 幂等保证
- 安全考虑（密钥不进日志、加密存储）

3. **自动更新追踪文档**：
   - `00-V1需求编号.md`：添加 V1-FR-005
   - `00-V1需求追踪矩阵.md`：添加功能 05 的映射行
   - `功能查找表.md`：添加 "API Key" → 功能 05

## 示例 3：记录冻结决策

### 场景

在开发过程中，发现 PRD 说"删除 API Key 物理删除"，但团队认为应该软删除以保留审计记录。需要做决策并记录。

### 操作

```
使用 spec-docs-pro 记录冻结决策：

背景：PRD 要求物理删除 API Key，但历史用量记录和审计日志需要关联 Key ID，物理删除会导致外键约束失败或数据孤立。

冲突：
- PRD 描述：DELETE 接口物理删除记录
- 代码实现需求：保留 Key 记录以维护审计链

备选方案：
A. 物理删除：简化存储，但需要级联删除或允许孤立记录
B. 软删除：添加 deleted_at 字段，保留记录但标记为已删除
C. 归档：移动到归档表

影响功能：
- 功能 05：API Key 生命周期
- 功能 14：网关鉴权
- 功能 18：用量采集
- 功能 20：用户记录查询

决定：采用方案 B（软删除）
```

### 预期输出

Agent 在 `docs/06-决策记录/V1-冻结决策.md` 中添加：

```markdown
## D010 API Key 删除策略

- 状态：已冻结
- 日期：2026-10-25
- 背景：PRD 要求物理删除，但历史用量和审计需要关联 Key ID
- 备选方案：
  - A. 物理删除：简化存储，需级联或允许孤立
  - B. 软删除：添加 deleted_at，保留记录
  - C. 归档：移动到单独表
- 决定：软删除（方案 B）
- 理由：
  - 用量记录和审计日志必须能追溯到原始 Key
  - 软删除实现简单，查询时过滤 deleted_at IS NULL
  - 存储成本可接受
- 影响：
  - 功能 05：DELETE 接口改为更新 deleted_at
  - 功能 14：鉴权时过滤已删除 Key
  - 功能 18、20：查询时自动 JOIN 包括已删除记录
  - 数据模型：api_keys 表添加 deleted_at 字段
  - Migration：0025_add_api_keys_deleted_at.sql
- 实施：
  - [ ] 更新功能 05 主文档的删除行为描述
  - [ ] 更新 V1-数据模型.md
  - [ ] 创建 migration
  - [ ] 更新相关功能的查询逻辑
```

同时更新受影响功能文档的引用。

## 示例 4：生成文档浏览器

### 场景

文档体系已经建立，包含 30+ 个功能文档，需要生成交互式浏览界面方便团队查阅。

### 操作

```
使用 spec-docs-pro 生成文档浏览器
```

### 预期输出

Agent 执行：

1. 扫描 `docs/` 目录下所有 markdown 文件
2. 提取每个文档的：
   - frontmatter（feature_id, version, status, domain）
   - 标题和 TOC
   - 功能编号
   - 完整内容（用于搜索）
3. 生成两个文件：
   - `docs/90-参考资料/产品文档浏览器.html`（单页应用）
   - `docs/90-参考资料/产品文档浏览器-文档数据.js`（约 500KB 数据文件）

### 使用浏览器

在浏览器中打开 HTML 文件，功能：
- **左侧文档树**：按目录结构展示所有文档
- **中间内容区**：渲染 Markdown 内容
- **右侧面板**：
  - 元信息（功能编号、版本、状态）
  - 目录跳转
- **顶部搜索**：搜索标题、内容、功能编号
- **阅读进度**：记录已读文档
