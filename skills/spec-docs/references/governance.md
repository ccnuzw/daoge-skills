## 1. 稳定编号

| 类型 | 格式 | 示例 | 分配时机 |
| --- | --- | --- | --- |
| 功能需求 | `Vx-FR-NNN` | `V1-FR-019` | 版本通过开发门禁、功能登记时 |
| 非功能需求 | `Vx-NFR-NNN` | `V1-NFR-017` | 性能、安全、容量目标冻结时 |
| 发布门禁 | `Vx-RG-NNN` | `V1-RG-012` | 定义发布/生产验收条件时 |
| 功能验收 | `ACNN` / `Vx-FR-NNN/ACNN` | `AC05` | 写功能主文档时；功能内唯一 |
| 跨功能验收 | `Vx-E2E-NN` | `V1-E2E-08` | 冻结端到端业务条件时 |
| 技术设计分支 | `B<功能号>-NN` | `B19-01` | 写技术设计时；功能号 + 两位序号 |
| 性能门禁用例 | `Vx-RG-NNN/PERFNN` | `V1-RG-012/PERF03` | 归属既有发布门禁，不建平行门禁 |
| 冻结决策 | `DNNN` | `D044` | 冲突裁决或口径变化时 |
| ADR | `NNNN` | `0009` | 有备选方案和长期后果的架构决策 |
| 功能文件 | `NN-中文名.md` | `19-余额冻结与调用扣费.md` | 领域目录内两位编号 |

规则：ID 一旦分配**永不复用、永不改变**；文档移动或改名不影响 ID；编号表是唯一登记处，其他文档引用编号而不是复制定义。跨版本演进的功能保持同一功能 ID，在功能演进矩阵里标注各版本状态。

插入式扩展：需要在不打乱既有编号的前提下插入用例或分支时，使用字母后缀（如 `V1-E2E-09B`、`B05-07A`），不要重排已有 ID 或复用已作废编号。

## 2. 状态机

区分两种状态，不要混用：

- **规格状态**（Draft / Ready）：文档是否具备开发输入，写在功能卡和执行空间表格里。
- **实现状态**（下表）：代码与证据实际做到哪一步，唯一维护在版本实现状态文档；功能文档与索引不得复制实现状态值。

| 实现状态 | 定义 |
| --- | --- |
| 规划中 | 已确定范围，尚未进入开发 |
| 开发中 | 已开始实现，未满足全部验收条件 |
| 基础实现 | 主链路有代码，仍存在专项测试或边界缺口 |
| 本地验证 | 实现与本地自动化通过，缺生产或真实外部依赖证据 |
| 待验收 | 实现与自动化验证完成，等待业务验收 |
| 已完成 | 需求、实现、测试、文档、验收全部闭环 |
| 阻塞 | 存在明确外部依赖，当前无法继续 |

唯一维护位置：`02-产品与版本/当前版本/V1-实现状态.md`。其他文档只链接状态表，不复制状态值；业务验收未完成不能标“已完成”；本地结果不能把状态推到“待验收”之后。

两个容易混淆的边界：

- **登记 ≠ 进入交付范围**：设计扩展或规划中的能力可以登记稳定编号、维护设计稿，但必须显式标注状态（例如“规划中；设计完成、运行时未开发”），不因登记视为已实现或已进入收费发布。版本完成口径只统计“已进入交付范围”的功能。
- **过程文档 ≠ 功能状态**：高风险修复清单、专项测试设计等轮次工作文档带日期，完成后把结论回写功能主文档与实现状态，不长期承担状态职责。

## 3. 三道门禁

### 版本进入开发门禁（未来版本 → 可开发）

未来版本默认只有概要文档，**不提前拆出功能规格**。解锁条件（全部满足，逐项判定）：

| 门禁 | 最低产出 |
| --- | --- |
| 范围冻结 | 版本规划、做/不做、依赖、成功标准；与前后版本无重复或隐式前置 |
| 全局约束 | 对全版本硬约束逐项做适用性检查，例外已冻结决策 |
| 稳定编号 | `Vx-FR/NFR/RG` 编号表，不依赖章节位置 |
| 架构 | 上下文/容器级架构、关键序列图、状态机，模块边界与数据所有权明确 |
| 接口 | Markdown 语义文档 + OpenAPI/JSON Schema 可校验 |
| 数据 | ER/关系、字段约束、索引、迁移与生命周期 |
| 功能规格 | 每个可独立验收目标一份主文档，章节齐全、口径一致 |
| 技术设计 | 全功能风险评审；高风险有独立设计，分支 ID 可追踪 |
| 测试 | Unit/Integration/E2E 分层矩阵；分支 ID 映射 AC；E2E 说明真实入口与最终状态 |
| 追踪 | PRD → 功能 → API/数据 → 分支 → AC/E2E，无孤立需求与无来源接口 |
| 安全与发布 | 安全基线、部署、回滚、恢复、证据空间 |
| ADR | 影响架构的决策有背景、备选、理由、后果 |

执行规则：复制结构不复制业务结论；可以按阶段进入（如 V1-P1），但阶段本身要满足完整门禁；门禁未过时 AI 只能调研、质疑、补规格，不得批量生成生产实现；影响资金、权限、数据删除、外部回调、跨系统状态的未决项一律阻止 Ready。

## 4. Definition of Ready / Done

### Ready（开工前，全部勾选）

- 目标版本、稳定功能 ID、主文档已确定。
- 用户故事、范围、不做范围清晰。
- 页面字段或系统输入已冻结。
- 接口请求、响应、鉴权、错误已冻结。
- 数据字段、状态、事务、幂等、删除行为已冻结。
- 文档冲突已进入冻结决策。
- 依赖功能状态支持开发。
- AC 覆盖正常/错误/权限/重复/并发/回滚。
- 每条 AC 已映射测试层级、目标资产、命令、证据状态。
- 已核对代码现状，差距清单明确。
- 高风险功能已完成独立技术设计与分支映射。
- 接口变化已同步机器可读契约。

未满足时保持“规划中”，不进入编码。模板句、占位符、待确认差异不算 Ready。

### Done（交付前，全部勾选）

- 后端业务与服务端校验完成；前端交互完成或明确不适用。
- migration、约束、事务完成。
- 接口与错误符合冻结契约。
- 单元、集成、前端测试通过；关联 E2E 通过。
- 日志、权限、敏感信息检查通过。
- 功能主文档、公共文档、实现状态同步。
- 验证记录含日期、环境、构建标识、命令、结果。
- 涉及真实支付/第三方依赖/生产运维时具有对应环境证据。

## 5. 变更联动矩阵

改一处必须同步的清单（这是“可维护”的核心）：

| 变更类型 | 必须同步 |
| --- | --- |
| 新增/修改接口 | 功能主文档接口章节、公共接口契约、openapi、前端类型、接口测试 |
| 新增/修改字段 | 功能文档接口/数据章节、数据模型、migration、序列化类型 |
| 新增错误码 | 功能错误矩阵、统一错误码、后端映射、前端提示、错误测试 |
| 页面交互变化 | 功能需求章节、界面规范（公共变化时）、前端测试 |
| 状态机变化 | 功能需求/数据章节、事务测试、E2E |
| 删除行为变化 | 依赖保护、接口、外键策略、确认交互、回归测试 |
| 权限变化 | 接口鉴权、页面守卫、越权测试、审计 |
| 资金逻辑变化 | 冻结决策、事务与幂等设计、流水、并发测试、E2E、发布门禁 |
| 当前完成度变化 | 功能验证记录、版本实现状态 |
| 编号/文件移动 | 编号表、索引、查找表、追踪矩阵、迁移映射（可能的话保持链接） |

## 6. 冲突处理

1. 收集冲突文档与代码证据，列出各口径。
2. 查是否已有决策；有则按决策执行，缺证据的一方改。
3. 没有决策 → 形成选择、影响、迁移方案，写入冻结决策（记录日期、状态、影响面）。
4. 同步功能主文档、公共契约、代码、测试。
5. 在文档变更记录中登记影响实现输入或验收口径的变化。

不允许调用方自行选择口径；不允许代码长期兼容两套语义而不记录。

## 7. 开发前强制读取顺序

给 AI（或新人）的读取清单，按此顺序读完再形成开发计划：

1. 仓库与当前目录的 `AGENTS.md`（如有）。
2. 功能开发流程 + 功能文档规范。
3. 全版本产品与交互约束。
4. 当前版本总览。
5. 冻结决策。
6. 需求编号表 + 需求追踪矩阵。
7. 目标功能主文档、风险分级、独立技术设计（如有）。
8. 相关公共契约（接口/数据/错误码/架构/安全/ADR）。
9. 版本实现状态 + 相关代码、migration、测试。
10. 关联端到端验收与发布门禁。

## 8. AI 完成前检查

**文档**：必需章节齐全；高风险有独立设计与分支映射；稳定 ID/OpenAPI/追踪矩阵同步；接口有 operationId 映射、可解析 OpenAPI 与错误矩阵；数据有约束/状态/事务/删除；AC 有映射；实现记录区分静态核验、实际测试、生产证据。

**代码与测试**：新字段贯穿 migration、领域、服务、接口、前端类型；错误码登记且一一对应；数据库唯一/外键/检查/幂等约束存在；权限在服务端校验；日志不泄露秘密；正常/边界/权限/重复/并发/回滚/页面状态覆盖。

## 9. 维护与归档

- 大能力处于设计期、还不满足功能规格拆分条件时，先在 `04-技术架构/当前版本/` 建一份“<能力>设计”单文件设计稿，并在编号表登记规划中的功能号；等范围与契约冻结后再拆成功能主文档，避免提前铺开空规格。
- 历史材料必须放入 `99-历史归档`，与当前权威文档物理隔离；归档内容默认不是开发输入。
- 路径迁移时先建新家、写“旧路径 → 新路径”映射，再删旧文件。
- `90-参考资料` 只放素材，不能覆盖当前结论。
- 被取代的决策标注“已被 Dxxx 取代”，保留原文。
- 文档结构或链接变化后运行 `check-docs`；严格证据门禁在发布前运行。

## 10. 禁止做法

- 只读产品总览，不读目标功能与当前代码。
- 只生成目录和通用段落，不写字段、错误和状态。
- 以代码默认值覆盖冻结需求而不记录决策。
- 只改后端，不同步前端类型、页面和契约。
- 只靠前端限制权限或字段；捕获数据库错误统一返回 500。
- 用浮点计算金额；日志输出完整 Key/Token/支付密钥/签名 URL。
- 把规划命令、本地 mock、静态核验写成生产验证通过。
- 为了让检查通过而伪造审批、时间、提交、制品、执行结果。
