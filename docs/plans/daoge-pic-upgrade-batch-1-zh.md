## 0. 前置

**本批是否触发规格书改动：否**（但**细化**了规格书 5.4 的一条归属，见下）

**细化说明（必须记录）**：规格书 5.4 把「枚举→人话翻译表 + 搜索 label 修正」整体归了一批。
核查后拆分：**前端侧**（翻译表 + 前端不再直接渲染 `result.purpose` 英文）留在一批；
**后端侧**（`queries.ts` 拼 label 时不再直接拼英文 `round.purpose`）**移到二批**，
因为那要动 `src/vnext/domain/queries.ts`，与本批「纯前端」的边界冲突。**规格书 5.4 的文字不做修改**（它描述的是完整工作），
本施工单记录这个拆分的理由——**这属于"细化"，不是"违背"**。

### 0.3 新增守卫桩（本批必须新建，先写成 fail）

1. **翻译表是唯一来源**——断言 `main.jsx` 与 `studio-search.jsx` 都从**同一个共享模块**取 purpose 的人话 label，
   且两处都不再出现硬编码的枚举→文案映射（防「选片翻译了、搜索裸奔」重演）。
2. **视图注册表完整性**——每个视图在注册表里都有「宿主视图 / 是否一级入口 / 所需上下文」三项，
   且一级入口集合与 `workbenchNavigationViews()` 一致。
3. **批次节点折叠有交互**——断言画布里存在**切换节点折叠的入口**（防「`collapsed` 字段存了却没有 UI」重演，见方案 4.3 的核查修正）。
4. **空状态三形态文案各不相同**——断言「没项目 / 搜索无果 / 筛选无果」三处用的是**三句不同的话**
   （现状是三处共用「还没有匹配项目。」，方案 4.7）。

- 前端改动经 `build:workbench` 产出、挂在根路径 `/assets/`，**不需要重启 daemon** → 改动**立即**在你的日用界面上可见。
