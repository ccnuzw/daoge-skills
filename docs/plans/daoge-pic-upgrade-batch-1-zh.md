# 第 1 批施工单 · 纯前端批（画布 + 检查器 + 交互 + 文案）

> 依据：方案文档 `studio-creator-centric-refactor-plan-zh.md`（下称「方案」）+ 实施规格书 `daoge-pic-upgrade-spec-zh.md`（下称「规格书」）
> **本批性质：纯前端。不碰后端、不碰 schema、不碰鉴权表。** 这是本批最大的价值——风险最低、见效最快、可以随时停。

## 0. 前置

**本批是否触发规格书改动：否**（但**细化**了规格书 5.4 的一条归属，见下）

**细化说明（必须记录）**：规格书 5.4 把「枚举→人话翻译表 + 搜索 label 修正」整体归了一批。
核查后拆分：**前端侧**（翻译表 + 前端不再直接渲染 `result.purpose` 英文）留在一批；
**后端侧**（`queries.ts` 拼 label 时不再直接拼英文 `round.purpose`）**移到二批**，
因为那要动 `src/vnext/domain/queries.ts`，与本批「纯前端」的边界冲突。**规格书 5.4 的文字不做修改**（它描述的是完整工作），
本施工单记录这个拆分的理由——**这属于"细化"，不是"违背"**。

### 0.3 新增守卫桩（本批必须新建，先写成 fail）

1. **翻译表是唯一来源**——断言 `main.jsx` 与 `studio-search.jsx` 都从**同一个共享模块**取 purpose 的人话 label，
   且两处都不再出现硬编码的枚举→文案映射（防「选片翻译了、搜索裸奔」重演）。
2. **视图注册表完整性**——每个视图在注册表里都有「宿主视图 / 是否一级入口 / 所需上下文」三项，
   且一级入口集合与 `workbenchNavigationViews()` 一致。
3. **批次节点折叠有交互**——断言画布里存在**切换节点折叠的入口**（防「`collapsed` 字段存了却没有 UI」重演，见方案 4.3 的核查修正）。
4. **空状态三形态文案各不相同**——断言「没项目 / 搜索无果 / 筛选无果」三处用的是**三句不同的话**
   （现状是三处共用「还没有匹配项目。」，方案 4.7）。

### 0.4 环境与影响提示

- 前端改动经 `build:workbench` 产出、挂在根路径 `/assets/`，**不需要重启 daemon** → 改动**立即**在你的日用界面上可见。
- **本批期间你的日常界面会持续变化**——这是预期的（本批就是在改界面）。若要一个安静的环境，先按规格书第 5 节起独立 workspace + 端口。
- **不动数据**：本批只改前端代码与文案，**不写库、不迁数据**，旧数据原样可用。

## 5. 验收清单

- [ ] 画布上单批次 = 一个节点，标着「第 N 批 · 完成 · X 张」；**双击能展开看到图**，再双击收起
- [ ] 展开的批次里**只有图**，没有「运行项 / 计划」节点
- [ ] 批次之间的**引用线自动出现**（有上游关系的地方）
- [ ] 新增一批后，**已有节点的位置没有挪动**（增量插入生效）；点「整理」才重排
- [ ] 选中一个批次 → **检查器出现**：属性、计划、待确认时的确认按钮、编辑计划入口
- [ ] 右键菜单**随对象状态变**（候选 / 已选定 / 已交付 三套菜单内容不同）
- [ ] 挑图：`→` 切下一张、`空格` = 就它了、`X` = 不行、`Enter` 放大；**3–4 张能并排比**；**能放大到 4× 以上**
- [ ] 出图时**占位格先立起来**，出一张填一张
- [ ] 全新用户首屏是「新建第一个项目」，**不是**「还没有匹配项目。」
- [ ] 批次失败时显示「完成 · X 张没成」+「重试这 X 张」，**没有弹窗**
- [ ] 质量指标在检查器 / 列表里能找到（不在 `project-overview` 独占）
- [ ] **切去别的标签页 / 别的应用，出图完成后标题栏出现未读提示**；已授权通知的会收到系统通知（未授权不报错、不反复索要）
- [ ] 全局搜索里**不再出现英文枚举**（如 `refinement`）
- [ ] 界面上不再出现「轮次」字样（该说「批次」的地方全部改到）
- [ ] `tsconfig.web.json` 第 1 档仍为 0 错；`lint` 全量 0 error；全套回归绿
