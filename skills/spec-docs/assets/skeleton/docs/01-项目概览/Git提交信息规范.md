# Git 提交信息规范

## 1. 基本格式

```text
<type>(<scope>): <中文描述>

<正文：做了什么 + 为什么>

Refs: <需求编号/决策编号>
```

## 2. 提交类型

| type | 含义 |
| --- | --- |
| `feat` | 新功能 |
| `fix` | 缺陷修复 |
| `refactor` | 不改变行为的重构 |
| `perf` | 性能优化 |
| `docs` | 仅文档 |
| `test` | 仅测试 |
| `build` | 构建、依赖 |
| `chore` | 杂项 |
| `migration` | 数据库迁移 |

## 3. 提交范围

用一级目录或领域名，例如 `auth`、`billing`、`gateway`、`docs`、`admin`。

## 4. 正文与页脚

- 说明“做了什么 + 为什么”；涉及需求、决策、migration 时写编号。
- 行为变化、破坏性变更、回滚方式写清楚；不要只写“update”。
- 不提交密钥、令牌、真实用户数据；示例值必须可公开。

## 5. 提交前检查

- [ ] 本地测试与类型检查通过；文档结构变化时运行 `check-docs`。
- [ ] 新增/修改字段已贯穿 migration、领域、接口与前端类型。
- [ ] 新增错误码已登记；日志未泄露秘密。
- [ ] 提交信息与实际变更范围一致，不夹带无关改动。

## 6. 历史改写

以仓库默认分支为准；禁止对已发布的分支做历史改写，修复使用新提交。
