# 模式：多版本规划与功能演进

适用：规划 V2 及以后的版本；建立或更新功能演进矩阵。

## 步骤

1. **读现状。** 版本路线图、当前版本总览、已有功能演进矩阵、实现状态。用户给出的版本主题和范围不再问。
2. **检查依赖。** 对每个规划版本问一次：依赖前序版本的哪些能力？这些能力当前是否稳定？有没有循环依赖或可以并行的版本？
3. **更新版本路线图。** 按 `assets/templates/version-roadmap.md`：版本总览表每个版本一行；每个规划版本写做 / 不做 / 依赖 / 进入条件；依赖关系画 Mermaid 图。
4. **每个规划版本建规划文档。** `02-产品与版本/后续版本/V{n}-{主题}.md`，只写目标、范围、依赖和进入条件。规划版本未过门禁前不分配 `V{n}-FR` 编号、不写功能主文档。
5. **更新功能演进矩阵。** 按 `assets/templates/feature-evolution-matrix.md`：总览表一行一条能力主线；每条主线一个 `##` 章节和一张 5 列阶段表；阶段名以 `V{n}`、`V{n} 发布门禁` 或 `后续` 开头。
6. **关联功能。** 当前版本的功能在 frontmatter 写 `track:`，值与能力主线章节标题一致。
7. **校验。** `check-docs.mjs --only EV001,EV002,EV003,EV004,EV005,VR001`，然后重新生成浏览器查看时间线。

## 不要做

- 不为了填满矩阵给每个版本都写阶段；没有变化就写 `-`。
- 不把规划写成承诺：阶段的“完成判定”是目标，不是完成声明。
