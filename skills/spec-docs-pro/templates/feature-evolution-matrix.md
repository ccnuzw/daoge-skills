# 功能演进矩阵

本文档以"能力主线"为单位，说明同一项产品能力如何跨版本演进。

---

## 1. 文档职责

本文档回答以下问题：

- 一项能力最早在哪个版本出现
- 后续版本具体增加了什么用户可感知行为
- 新阶段依赖哪些既有功能和发布门禁
- 达到什么结果才算完成该阶段
- 当前内容是现行功能、未来规划、历史迁移还是独立增强

本文档不替代其他权威来源：

- 产品愿景和完整范围以[产品蓝图](产品蓝图.md)为准
- 版本顺序和边界以[版本路线图](版本路线图.md)为准
- V1 功能行为以[V1 功能规格](../03-功能规格/V1/README.md)为准
- 后续版本的功能行为以各版本的功能规格为准

## 3. 身份与权限演进

**能力主线说明**：用户身份、API Key 管理、权限控制的跨版本演进

| 阶段 | 用户可感知变化 | 依赖与边界 | 完成判定 | 状态与来源 |
|------|---------------|-----------|---------|-----------|
| V1 个人账户与 Key | 用户可注册登录；创建、禁用和删除个人 API Key；每个 Key 独立计费 | 用户、Key 和账号必须隔离；一个用户多个 Key | 用户能注册、登录、管理 Key 并成功调用 | 当前版本：[V1-FR-001～005](../03-功能规格/V1/01-身份与权限/) |
| V2 Key 级限流与安全 | 每个 Key 可设置每分钟请求限制；超限自动阻断；Key 过期自动禁用 | 只增强 V1 个人 Key；不创建项目概念 | Key 限流在多实例下生效；过期 Key 无法调用 | 规划：[V2 稳定网关](后续版本/V2-稳定网关.md) |
| V4 项目与预算控制 | 用户可创建项目；为项目设置预算上限；项目内 Key 共享预算；超预算自动停服 | 不引入组织；只是个人用户的多项目 | 项目预算生效；超额自动拒绝请求 | 规划：[V4 商业支付](后续版本/V4-商业支付.md) |
| V8 组织与企业权限 | 组织账户；成员邀请与角色；企业 SSO；组织级 Key 和预算 | 基于 V4 项目概念扩展为组织 | 组织管理员可管理成员；支持 SAML/OIDC | 规划：[V8 企业化](后续版本/V8-企业化.md) |

## 5. 网关调用演进

**能力主线说明**：API 调用协议、流式处理、重试容错的跨版本演进

| 阶段 | 用户可感知变化 | 依赖与边界 | 完成判定 | 状态与来源 |
|------|---------------|-----------|---------|-----------|
| V1 同步调用 | 支持 Chat Completions 接口；同步返回；基础错误处理 | 实现 OpenAI 兼容协议 | 用户可成功调用并获得响应 | 当前版本：[V1-FR-015](../03-功能规格/V1/03-网关调用/) |
| V2 流式与重试 | Server-Sent Events 流式输出；失败自动切换备用 Key；幂等设计 | V1 同步调用稳定；不新增协议 | 流式可被 SDK 消费；失败不重复扣费 | 规划：[V2 稳定网关](后续版本/V2-稳定网关.md) |
| V6 高级调度 | 智能路由（成本、延迟、成功率）；流量分配策略；健康检查 | V2 流式和容错稳定 | 路由策略生效；故障自动摘除 | 规划：[V6 高级调度](后续版本/V6-高级调度.md) |

## 7. 维护规则

### 修改原则

- 每个能力主线章节**必须使用 5 列表格**
- 表格列：阶段 | 用户可感知变化 | 依赖与边界 | 完成判定 | 状态与来源
- 阶段列格式：`V1 简短描述`（如 "V1 基础账户"）
- 不使用层级结构（### 3.1, 3.2）

### 新增能力主线

1. 在"能力主线列表"中添加一行
2. 新增对应的章节（## X. 能力名称演进）
3. 添加 5 列表格，至少包含 V1 的一行

### 新增版本阶段

在对应能力主线的表格中添加新行，按版本顺序排列
