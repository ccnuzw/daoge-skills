# 模式：初始化文档体系

适用：新项目，或现有项目还没有 spec-docs 风格的 `docs/`。

## 步骤

1. **确认输入。** 需要：项目名、一句话定位、首个版本和已知后续版本、业务领域、技术栈（可选）、已知功能清单（可选）。用户已经给出的不再问；缺失的一次性问完。目标目录已有 `docs/` 时，先列出现有结构，问清是合并、迁移还是另建，不覆盖已有文件。
2. **选规模。** 按 [doc-structure.md](../doc-structure.md) 第 2 节判断 S / M / L，告诉用户选择和理由。
3. **生成目录和文件。** 按 doc-structure.md 第 1 节的路径创建，需要模板的文件从 `assets/templates/` 复制后填写：
   - `docs/README.md` 标题写成“{项目名} 文档中心”，浏览器据此识别项目名。
   - 版本路线图的版本总览表登记全部已知版本；每个规划版本在 `后续版本/` 下建规划文档（硬规则 11）。
   - 领域建成 `03-功能规格/V1/01-{领域}/` 等目录，在 `03-功能规格/V1/README.md` 列出。
   - 已知功能在 `00-V1需求编号.md` 分配编号，在 `V1-实现状态.md` 登记为“规划中”。功能主文档不在这一步批量生成。
   - 每个目录的 README 写明“本目录放什么、入口文件是哪个”。
4. **校验。** 运行 `node <skill>/scripts/check-docs.mjs --docs docs`。新建体系应当 0 错误；警告逐条处理或说明原因。
5. **交付说明。** 列出生成的文件树（只列实际生成的）、你做的假设、下一步建议（通常是“为 V1-FR-001 写规格”）。

## 不要做

- 不生成没有内容的空壳文件来凑数量。
- 不把模板示例或其他项目的领域、接口、错误码搬进新项目。
- 不在功能主文档里写实现状态。
