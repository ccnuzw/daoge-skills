# {{VERSION}} E2E 执行手册

## 执行前检查

1. 生成唯一 `run_id`，记录操作者、环境、commit、build 和配置摘要。
2. 执行环境 health/ready 与迁移版本检查；失败时批次记为 `environment_failed`。
3. 确认依赖真实性模式、测试专用开关和日志脱敏策略。
4. 建立当前批次夹具并保存对象 ID，不输出秘密。
5. 确认报告目录可写，失败批次不会覆盖历史报告。

## 运行顺序

| 阶段 | 用例/领域 | 前置 | 原因 | 失败后是否继续 |
| --- | --- | --- | --- | --- |
| A | 身份与基础数据 | 环境预检 | 建立后续旅程主体 | 否 |
| B | 核心成功旅程 | A | 验证主价值链和最终状态 | 否 |
| C | 拒绝、重复与依赖失败 | B | 证明零副作用、幂等和补偿 | 按风险决定 |
| D | UI 与角色回归 | A | 验证用户可见完整状态 | 是 |

单用例必须自行建立依赖夹具，不得依赖其他批次遗留状态。

## 每个用例的统一步骤

1. Arrange：建立或查询本批次夹具，保存对象 ID 和前置状态。
2. Act：通过公开入口触发行为，记录 request_id 和外部调用计数基线。
3. Assert response：校验协议、错误、字段和用户可见结果。
4. Assert side effects：校验数据库终态、审计、队列、外部调用和不变量。
5. Replay/Failure：执行适用的重复、并发、超时、失败和补偿断言。
6. Archive：保存脱敏报告、失败步骤和查询结果。

## 失败诊断

| 失败类型 | 标记 | 必须保留 | 禁止操作 |
| --- | --- | --- | --- |
| 业务断言 | failed | 首个失败步骤、request_id、响应和副作用 | 手工修终态后改成 passed |
| 环境故障 | environment_failed | 健康检查、配置摘要和受影响用例 | 计入业务失败或通过 |
| 依赖替身失效 | invalid | 替身健康、请求记录和影响范围 | 静默跳过 |
| 证据缺失 | evidence_incomplete | 已执行命令和缺失项 | 用文字结论替代报告 |

资金、权限、删除、重复副作用或数据不变量失败时立即停止相关用例，并隔离测试主体。

## 证据保存

报告必须包含 `run_id`、环境、依赖模式、commit/build、命令与退出码、逐用例结果、脱敏证据、失败/跳过和残余风险。更新实现状态前先校验机器报告，不能以本文档或历史描述替代执行结果。

## 清理

1. 成功批次按策略清理当前 `run_id` 资产。
2. 失败批次先保存证据，再决定保留或清理。
3. 撤销临时秘密、网络授权、测试证书和功能开关。
4. 确认无后台任务、租约、队列消息或外部测试订单残留。
5. 清理失败必须记录责任人和后续处置，不能隐藏批次结果。
