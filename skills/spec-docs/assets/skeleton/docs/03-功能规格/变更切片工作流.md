# 变更切片工作流

变更切片用于记录一次可独立审查、实现和验证的增量修改。每个切片使用稳定 ID `Vx-CS-NNN`，不替代功能主文档；它只描述本次变更相对已冻结基线的差异。

## 1. 适用范围

- 修改既有功能的接口、数据、权限、状态、验收或发布行为。
- 跨功能但可以明确主功能、依赖功能和回滚边界的增量变更。
- 需要在完整功能文档之外快速审查影响面的修复或演进。

不适合把一次不可独立验收的大型版本拆成大量没有边界的切片。

## 2. 编号和目录

切片 ID 格式为 `V1-CS-001`。建议放在：

```text
docs/07-变更切片/V1/V1-CS-001-变更标题.md
```

切片必须引用至少一个稳定功能 ID；跨功能变化应列出主功能和依赖功能。

## 3. 最小闭环

1. 写清基线、目标和不变项。
2. 列出受影响的文档、接口、数据、代码、测试和发布资产。
3. 记录冲突及冻结决策，不用当前代码默默覆盖需求。
4. 把每个验收条件映射到测试命令和证据状态。
5. 完成后回写功能主文档、公共契约、追踪矩阵和实现状态。

## 4. 只读分析

```bash
node scripts/change-impact.mjs --dir . --slice V1-CS-001
node scripts/change-impact.mjs --dir . --feature V1-FR-001
node scripts/policy-calibrate.mjs --dir .
```

两个命令都只输出 JSON，不修改项目文件。`change-impact` 根据稳定 ID、`operationId`、实体和路径引用报告关联文档；`policy-calibrate` 根据实际文档库存和现有 policy 输出适配建议。
