## 执行顺序

1. `calibration`：确认脚本、指标、夹具和安全范围。
2. `steady`：以批准 Profile 建立有效稳态样本。
3. `overload`：验证容量拒绝边界，不把拒绝伪装成错误。
4. `recovery`：降载后观察延迟、资源、错误和业务终态恢复。
5. `correctness`：核对资金、用量、幂等、Hold、队列和 request_id。

任何资金/数据不变量失败都使整批失败，不因其他指标达标而降级。

## 停止条件

- 负余额、重复副作用、用量丢失、Hold 无法终结或 request_id 关联断裂。
- 非预期 5xx/超时放大、服务不 ready、数据库耗尽或无界 RSS/队列增长。
- 压测机、模拟器或共享租户噪声使有效到达率或指标无效。
- 敏感信息写入日志、报告、标签或外部请求。
- 未授权外部调用或影响非测试租户。
