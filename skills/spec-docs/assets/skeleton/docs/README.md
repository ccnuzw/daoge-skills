## 推荐查找顺序

1. 只知道业务词：先查 [功能查找表](03-功能规格/{{活跃版本}}/功能查找表.md)。
2. 知道功能编号或名称：从 [功能规格索引](03-功能规格/{{活跃版本}}/README.md) 进入主文档。
3. 知道所属领域：进入对应领域目录，先读目录内 `README.md`。
4. 判断是否实现：统一查看 [{{活跃版本}} 实现状态](02-产品与版本/当前版本/{{活跃版本}}-实现状态.md)，不要从需求文档猜测。
5. 开始开发：先读功能主文档，再读技术设计（如有），最后按“工程落点”进入代码。

不需要顺序阅读整个 `docs` 目录。

## 命名规则

- 人工阅读的文档使用“编号 + 中文主题”，例如 `19-余额冻结与调用扣费.md`。
- `README.md`、`openapi.yaml`、API 路径、数据库字段和代码标识保留行业约定名称。
- 功能编号、需求编号、分支编号和 ADR 编号必须保持稳定；移动文档不能改变这些追踪 ID。
- 尚未进入开发的版本只维护一份版本规划，进入开发门禁后才拆成功能规格。
- 历史材料必须放入 `99-历史归档`，不得与当前权威文档并列。
