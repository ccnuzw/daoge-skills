## 0. 一页结论

界面现在的问题**不是好不好看，是没有标准**：9 个页面容器 6 种宽度、10 套页头写法、13 个断点（同一断点两种写法）、1157 个色值、0 个设计 token；首屏之上最多 9 条带；`App` 一个组件 1775 行。用户每换一屏都在重新学版式，创作者最关心的东西（图、批次、计划）反而被压在 chrome 下面。

### 十条标准（详表见 §4）

| # | 标准 | 一句话判据 |
|---|---|---|
| S1 | **空间与主次预算** | 首屏主区占比：工作台面 ≥60%、列表面 ≥55%、阅读面 ≥45%；**顶部 chrome ≤180/200/240px**；无状态条时**第一个业务元素出现在 y ≤190/210/240px** |
| S2 | **骨架** | 纵向只有三段：topbar(56) + 状态槽(0/1 条，≤44) + 主区；底部槽(44)贴底 |
| S3 | **宽度** | 页面宽度只有 `wide 2400 / standard 1180 / narrow 820` 三档，由 view 注册表声明 |
| S4 | **视觉 token** | 颜色 ≈30 个语义 token、字号 8 档、间距 6 档、圆角 4 档、阴影 3 档、层级 4 层；字面量只允许出现在 `tokens/` |
| S5 | **密度与层级** | 每屏 ≤4 档字号、≤2 种语义强调色、页面级按钮 ≤7；**一行里 ≤2 个数字** |
| S6 | **断点** | 只有 1280 / 900 / 640（+ reduced-motion）；窄屏触控 ≥44×44 |
| S7 | **状态与反馈** | 状态槽同一时刻只渲染一条；同一事实只有一个常显位置 |
| S8 | **文案与术语** | 继续以 `terminology.mjs` 为单一来源；布局实现词不进 creator 面 |
| S9 | **无障碍** | 凡定义 `:hover` 的样式块必须同时定义 `:focus-visible`；对话框焦点约束、live region、reduced-motion 沿用既有资产 |
| S10 | **规模与性能** | 大列表虚拟化 + 分页；画布节点渲染上限沿用既有常量；缩略图必须用缩略 URL |

### 主 / 次 / 系统：三层定义（全站通用）

| 层 | 是什么 | 常显预算 | 位置规则 |
|---|---|---|---|
| **主**（Main） | 当前任务的产出与决策：图、批次、计划、交付物、画布 | ≥60% 首屏面积 | 永远居中、最大、最先出现 |
| **辅**（Support） | 定位与切换：面包屑、rail 分区、筛选、搜索、视图选项 | ≤3 条常显，合计 ≤200px 高（见 S1） | 贴边（顶/左），不占主区高度 |
| **系统**（System） | 状态、诊断、设置、日志、密钥 | 默认只有 rail 一张状态卡 | 折叠为一行结论，按需展开；只在阻挡当前动作时浮出 |

一句话：**主区必须一眼可见，辅只能贴边，系统默认闭嘴。**

### 五个批次

`A 底座（token + 模板 + 状态槽 + 审计覆盖层）` → `B 外壳（顶栏/面包屑/rail）` → `C 创作平台（主体）` → `D 三面（资产/交付/资料）` → `E 拆分（L0–L6 落地）+ 守卫收口`

## 2. 诊断（全部可复算）

### F0 上半屏被占（这是最要命的一条）

**口径**：`内容占比 = 主区可见高度 / 视口高度`（1440×900，不滚动，未选中任何东西的默认态）。

创作平台的纵向账（各值取自 CSS，合计为**估算**，实测由 §8.1 的审计覆盖层给出）：

| 段 | 高度 | 出处 |
|---|---|---|
| `work-surface` 上内边距 | 32 | `styles.css:31` |
| `workspace-chrome`（页头 52 + 上下文条 36 + 边距 26） | ≈114 | `styles.css:520-521`、`main.jsx:3286-3288` |
| `request-dock`（输入行 54 + 间隙 8 + agent 行 17 + 外边距 10） | ≈89 | `styles.css:1464-1467,1490` |
| `lineage-toolbar` | ≈45 | `styles.css:218` |
| `lineage-focus-strip`（三张卡） | ≈90 | `styles.css:222` |
| `lineage-filterbar`（按钮 34 + 上下外边距 28） | ≈62 | `styles.css:258` |
| `lineage-searchbar` | ≈50 | `styles.css:260` |
| **顶部合计** | **≈482** | |
| 画布元素声明高度 | `calc(100vh - 210px)` = 690 | `styles.css:591` |
| **画布实际可见** | **≈418 = 46%** | 估算 |

也就是说：**创造者打开创作台，近一半竖屏花在「说明自己在哪里、能做什么」上，画布只拿到 46%。** 而且画布自己声明的 690px 永远显示不全——它下面还压着 482px 的 chrome。

同一口径下的其他屏（估算）：资产管理 ≈52%（有导入引导与选片条时降到 ≈40%）；资产交付 ≈55%；资料区 ≈70%（阅读面本身留白多，问题不在这里）。

**这条标准是新增的硬指标**：见 S1。

### F1 没有骨架：每屏各造一套页头与宽度

9 个页面容器 6 种宽度：`.asset-stage`/`.run-stage`/`.error-strip` 1560（`styles.css:32`）、`.overview-stage` 1560（`:39`）、`.prompt-stage`/`.guide-stage` 1120（`:42`）、`.project-index-stage`/`.project-overview-stage`/`.project-tasks-stage` 1120（`:44`）、`.guide-stage-full`/`.creative-library`/`.creator-delivery`/`.shared-assets-stage` 1180（`:46,54,58,86`）、`.lineage-stage` 1680（`:217`）。`.run-stage` 的宽度被同文件改写三次（`:32`→`:33`→`:839`）。「页头 + 操作区」共 10 套类名族。

### F2 纵向堆叠：首屏之上最多 9 条带

shell 渲染顺序固定（`main.jsx:3276-3298`）：chrome → 队列（常驻）→ 7 条条件状态条 → 内容。CSS 侧 17 个含 `strip` 的类选择器，没有统一状态位。同一条事实多处置顶：provider 退避在 rail 状态卡、队列底栏（`request-queue.jsx:70`）、生成服务页（`provider-settings.jsx:381`）三处。

### F3 入口重复：同一目的地在两套导航里同时出现

rail 一级入口（`workbench-navigation.jsx:9-19`）与上下文条 5 个页签（`main.jsx:707-712`）中，「资产管理」「创作平台」同名同址常显。源码里 `view:'lineage'` 15 处、`view:'assets'` 4 处、`view:'deliveries'` 4 处、`view:'runs'` 4 处、`view:'tasks'` 3 处。上下文条一行混排四类东西：上下文切换 + 动作 + 导航 + 会话语境。vNext 规格 §12 已明写「不得默认同时展示四层持久导航」。

### F4 视觉没有底座

`styles.css`：1512 行 / 255,594 bytes；1970 规则、2211 选择器、≈8615 声明；68 个 `@media`、13 个宽度断点（`(max-width: 800px)`×3 与 `(max-width:800px)`×7 是同一个断点）；**1157 个六位色值**、158 个 rgba、27 种字号、20 种 gap、52 种 min-height、7 种圆角；`!important` 8 处；设计 token **0** 个（只有 4 个布局变量，`styles.css:652`）。覆盖式补丁常态化：`.asset-select-control`（`:43`→`:45`）、`.surface-header`（`:32`→`:521`→`:595`→`:606`）、`.lineage-canvas` 高度四改（`:317`→`:591`→`:514-515`）。

### F5 体量失衡：改不动

`App` 1775 行（`main.jsx:1546-3320`），一段挂 8 个条件浮层（`:3270-3313`）；`CreativeLineageCanvas` 1159 行（`creative-lineage-canvas.jsx:499-1657`）；另有 `GenerationHistory`、`PromptWorkspace`、`ProviderSettings`、`CreatorDelivery` 四个复合件。布局改动要在一千七百行里找落点——**这就是「界面优化」长期停在改文案的根本原因**。

### F6 主体被埋：画布之上 4 条 chrome

`lineage-toolbar`（最多 9 个按钮）→ `lineage-focus-strip`（条件卡含两个导航按钮 + 视角 + 4 指标）→ `lineage-filterbar`（筛选 + 背景 + 保存态 + 一长串统计）→ `lineage-searchbar` → 画布（`creative-lineage-canvas.jsx:1297-1340`）。四条横贯全宽。

### F7 已经很好、不许动的资产

术语治理（`terminology.mjs` 单一来源 + 三面隔离 + 守卫）；路由归一化与深链不变量（`workbench-route.mjs`）；无障碍原语（`AccessibleDialog`、`accessible-dialog-model`、`:focus-visible`、reduced-motion）；事件与刷新（`use-studio-events` + `refresh-coordinator` + 快照恢复）；三种画布视角（`creative-lineage-canvas.jsx:22-27,419-423`）；挑图快捷键、占位符、撤销窗口。**一律「接线，不重做」。**

## 3. 以人为本：创作者的六个瞬间

标准不是从「界面元素」推出来的，是从**人真正会做的六件事**推出来的。每条瞬间给出「第一眼 / 手边 / 不许挡」，再落成 §4 的标准条款。

| # | 瞬间 | 第一眼要什么 | 手边要什么 | 不许挡 | 落地条款 |
|---|---|---|---|---|---|
| 1 | **进站**（今天做哪个项目） | 项目列表 + 最近活动 | 新建项目 | 统计墙、任务/批次、交付历史 | S1-S3、§7.1 |
| 2 | **说一句**（想让它干什么） | 输入框、agent 在不在场 | 发起、改一下、就这么出 | 被推到内容下方或藏进二级页 | S2、§5.9 |
| 3 | **看它长出来** | 批次框里逐张填图（占位先行） | 暂停 / 取消 / 重试这 N 张 | 跳页、弹窗、进度数字占主角 | §5.8、§7.3 |
| 4 | **挑图**（这批哪几张行） | 图够大、够多、能放大 | ←/→/空格/X/Enter、就地「按这几张再来」 | 把挑图搬去资产管理页 | §5.7、§7.3 |
| 5 | **交出去** | 选中的图 + 交付名 | 导出、历史 | 把交付做成第二个资产浏览器 | §7.5 |
| 6 | **出事了** | 一句人话（谁的错、下一步） | 重试 / 恢复 / 去后台核实 | 术语、状态码、静默失败 | S7、§5.11 |

**由这六条反推出的三条硬要求**（也是 S1 的来源）：

1. **主区必须在首屏且够大**——瞬间 3、4 靠面积，不靠点击；
2. **辅助只能贴边**——瞬间 2 的输入框贴底，瞬间 1 的列表居中，导航不占内容高度；
3. **系统默认闭嘴**——瞬间 6 之外，状态/诊断/设置不出现在主区。

> **交互层面还有八条硬判据**（「手的顺序对不对」）：见 **§3.1**。
> 它防的是「版式对了、顺序错了」——例如把「选中 + 说一句」做成互斥、把批量动作塞进常驻工具条。

| # | 判据（创作者的习惯） | 现状 | 本方案的落点 |
|---|---|---|---|
| **I1** | **「选中 + 说一句」必须能同时成立**——圈住两张图再说一句，是编排的主路径（宪法 §4.3 第四刀） | 圈选已能进 composer（第 3 批 G1） | ⚠️ **不得把 composer 与选片做成互斥**：底部槽**常显 composer**（idle 48 不消失），选片条叠在它**上方**的展开层（见 §5.9 与 G6 改法） |
| **I2** | **挑完就地接下一步**——挑完那一刻最想做的是「按这几张再来」（§4.8 第四条） | 选片条 / 资产卡 / **放大层**都有「用这张 / 这组继续」 | 三处**都要保留**（§5.7 写明）；批 C 收敛时一个不许丢 |
| **I3** | **已出的图立即可用**——先出的几张可以先挑，不必等整批（§4.9 配套 1） | 占位逐张替换已实现 | 批 C 的占位美化**不得挡住「可选中/可评审」**（§7.3 写明） |
| **I4** | **选中是一切动作的前提**——有作用对象 → 浮条/右键；没有 → 工具条（§4.4 判据） | 画布浮条已实现 | §5.5 工具条只放「怎么看 + 页面级创建」；**批量动作属于「有作用对象」，去浮条**（现方案把它放工具条右侧，与 §4.4 冲突，已改） |
| **I5** | **控制就地**——暂停/取消/重试在批次节点上，不跳页（§4.9 配套 2） | 批次节点 + 卡片都有 | §5.8 写明：**节点就地动作优先**，检查器里的是第二条路，不是唯一路 |
| **I6** | **视口聚焦（位置不变）**（§4.3「一份布局 + 视口聚焦」） | ✅ **能力已在**：选中 + `F` / 「适应选择」按钮 / 右键菜单；另有「适应全部」。缺的只是「双击飞过去」这个**手势** | **D8 决议 ①（2026-09-19）：不新增手势**——双击位已被「折叠/展开」（批 1）与「新建任务」（批 3）占用；宪法 §4.3 已按实施修正（不新增手势，位置不变不变） |
| **I7** | **出完了叫我**——离开画布也知道（第 1 批 C5，已实现） | 标题未读 + 通知 | §5.2 顶栏补「未读完成」的位置（标题 + 指示点），批 B 不得丢 |
| **I8** | **非出图回复显示在发起处 + 追问就地能答**（§4.5） | 卡片四态 + 就地回答已实现 | §5.9 写明：三种形态都要**能在底栏读完并就地回答**，不许只给「去看全部记录」 |

> **判定方式**：I1–I5、I7、I8 在批 B/C/D 的验收清单里各出一条可见现象；I6 见 D8。
> **这一节是「布局宪法」与「创作宪法」的接缝**：§4 的标准不许把这一节的顺序改坏——改坏了就是「好看但不好用」。

## 4. 标准（Standards，可量化、可守卫）

### S1 空间与主次预算 ★

**公式**（审计覆盖层按此计算，见 §8.1）：

```
内容占比   = 主区可见高度 / 视口高度            （首屏，默认态，不滚动）
顶部 chrome = (topbar + 状态槽 + 页头 + 工具条) / 视口高度
首元素 y   = 第一个业务元素（图/行/画布）到视口顶部的距离
```

| 屏幕类型 | 内容占比 | 顶部 chrome | 首元素 y（无状态条） |
|---|---|---|---|
| **工作台面**（创作平台、生成历史、批次清单） | **≥60%** | ≤180px（≤20%） | ≤190px |
| **列表面**（项目、任务、资产、交付） | **≥55%** | ≤200px（≤22%） | ≤210px |
| **阅读面**（资料、手册、疑难、设置） | ≥45% | ≤240px（≤27%） | ≤240px |

补充硬规则：

1. 表内数值按 **1440×900 视口**计；其他视口按比例判断，但 **px 上限恒定**（写死像素，不写死比例）。
2. 无状态条时，**第一个业务元素必须出现在 y ≤190px（工作台面）/ ≤210px（列表面）/ ≤240px（阅读面）**；出现状态条时各放宽 44px。
3. **页面级常驻按钮 ≤ 7 个**，其余进「更多 ▾」。
4. **一行里最多 2 个数字**（禁止统计长句）。统计一律进浮层或检查器。
5. 底部槽 idle 高度 ≤48px；展开（有请求卡片）**≤320px 且不超过视口 35%**，且**必须让内容让位，不许遮挡**。
   ⚠️ **口径说明（2026-09-19 审计改）**：原写「展开 ≤240px」——但第 4 批之后一张卡片自带**回执行（1–3 行）+ 就这么出 / 改一下**，
   240px 装不下两张卡。所以改为「**320px 或视口 35%，取小者**」，并要求：
   ① 卡片本体的回执行默认**只显示前 2 行**、点「展开」看全；② 超过 3 张卡的详情进 `Aside`（§5.9）。
6. 段高度上限（写死）：topbar **56** / 状态槽 **44** / 页头 **工作台面 ≤56、列表与阅读 ≤88** / 工具条 **48** / 底部槽 idle **48**。
   → 校验：工作台面 56+56+48 = **160 ≤180 ✓**；列表面 56+88+48 = **192 ≤200 ✓**；阅读面同上但可再加一行说明 ≤240 ✓。
7. **底部槽预算（新增，与第 5 条配套）**：底部槽**不计入「顶部 chrome」**，但**计入主区高度**——
   `内容占比 = (视口高 − 顶部 chrome − 底部槽常驻 48) / 视口高`。展开态按**让位后**重算并向审计层报告两个数
   （`折叠态占比` 与 `展开态占比`）。**达标判据只看折叠态**；展开态不得遮挡（不再单独设阈值）。

### S2 骨架

- 纵向三段：`topbar(56, sticky)` → `status-slot(0 或 1 条, ≤44, sticky)` → 主区；`bottom-slot(44, sticky 贴底)`。
- `work-surface` 仍是唯一滚动容器；主区自己滚，页面不再有第二个滚动条。
- 常驻横带（顶部 + 底部）**总数 ≤ 3**。

### S3 宽度与栅格

| 档 | 值 | 用于 |
|---|---|---|
| wide | 2400 | 创作平台、生成历史、批次清单、规则资料 / 共享素材 / 创作手册、**资产管理 / 回收站 / 资产交付** |
| standard | 1180 | 项目、任务 |
| narrow | 820 | 疑难、计划审阅 |

> ⚠️ **2026-09-20 标准修订**：`wide` 由 **1680 → 2400**；资料三页由 `narrow` 提到 `wide`（刀哥：主内容区太窄，
> 左右空一大片，利用率要到 90%+）；资产 / 回收站 / 交付由 `standard` 提到 `wide`（刀哥：这三屏才是真正吃空间的模块——
> 选图看图、对比、打包交付）。顶栏 / 状态槽 / 页面列 / 画布舞台**共用这一条列**（S19），所以抬高一档 = 整屏一起变宽、
> 左缘仍对齐；实测 1440/1920/2560 视窗利用率 100%，3008 视窗 90%。数据与截图见 §12 的 S26 / S27。

- 宽度由 view 在注册表声明（`layout` 字段），**任何 view 不得自写 `max-width`**。
- 栅格：内容面 12 列 / 间距 16；阅读面单列 + 8 栅距；媒体网格用 `repeat(auto-fill, minmax(220px, 1fr))` 起步。

### S4 视觉 token

| 组 | 内容 |
|---|---|
| 颜色 | 浅面：`--surface-page/card/raised`、`--ink-1/2/3`、`--line-1/2`、`--accent`、`--accent-strong`、四组状态色（各配 `-bg`/`-ink`）；深面（rail）：`--rail-bg/line/ink-1/ink-2/accent`。**深面颜色只在 rail 作用域内使用** |
| 字号 | `10 / 11 / 12 / 13 / 15 / 20 / 26 / 34` 八档 |
| 间距 | `4 / 8 / 12 / 16 / 24 / 32` 六档（+2px 发丝线） |
| 圆角 | `4 / 8 / 12 / pill` |
| 阴影 | `--shadow-1`(卡片) / `-2`(浮层) / `-3`(对话框) |
| 层级 | `--z-sticky:10` / `--z-slot:20` / `--z-drawer:30` / `--z-dialog:40` |
| 动效 | 过渡统一 `180ms ease`；`prefers-reduced-motion` 全局抑制保留 |

**落地方式**：新增 `web/src/tokens/`，是全仓**唯一允许出现字面量**的地方；`styles.css` 拆为 `tokens → base → primitives → components → organisms → templates → surfaces/*`，入口仍是单一 `styles.css`（`@import` 汇聚，构建产物不变）。

### S5 密度与信息层级

- 每屏 ≤4 档字号；≤2 种语义强调色（+中性）。
- 每屏可见说明性段落 ≤3 段，其余进 tooltip / 手册。**优先「移位」，不是「删除」**（2026-09-19 审计补）——
  上限是布局约束，不是删掉创作者需要的那句解释的理由（与 §10 风险表同一条）。
- 表格/列表默认密度：行高 44（紧凑 36 / 舒适 52），由工具条的「密度」开关切换（可选实现）。
- 图标只用一套（现 `lucide-react`），尺寸只有 14 / 16 / 17 / 20 四档。

### S6 断点与触达

`1280`（rail 收窄 / 检查器变抽屉）、`900`（rail 变顶部横条、页面单列）、`640`（单列 + 触控 ≥44×44）。此外只允许 `prefers-reduced-motion`。**被删除的旧断点必须在施工单里逐条列出。**

### S7 状态与反馈

- 状态槽优先级（写死在模型里并加测试）：`runtime-danger > provider-outage > connection-error > request-error > cancel-undo > notice`。
- **alert 级永不折叠，且必须保持 `role="alert"` / `aria-live="assertive"`**——`runtime-danger`、`provider-outage`、
  `connection-error` 三条都属这一级（2026-09-19 审计补：`provider-outage` 是第 4 批新增的首屏级提示，
  若在收敛时被降级成 polite 或折叠进「还有 N 条」，就等于把「整层不可用」藏起来了）。其余低优先级进「还有 N 条」。
- 同一事实只有一个常显位置（rail 状态卡）；其他位置只允许在「它正在阻挡当前动作」时出现。
  **已定落点**：provider 退避/限流的**常显结论**在 rail 状态卡（消费 `/api/providers.runtime`），
  队列底栏只在它正在拖慢当前出图时提示一次（`providerRuntimeNotice`）——两处不许各说各话。
- 加载/空/错误三态是每个数据区的强制项（空态按原因分句：无数据 / 搜索无果 / 筛选无果）。

### S8 文案与术语

- 界面词以 `terminology.mjs` 为单一来源；本方案新增布局词（`创作平台`、`检查器`、`队列`、`说一句`、`面包屑`）必须登记，且**不得进入 creator 面**。
- 数字后面永远跟单位（「4 张」「2 条」），状态后面永远跟下一步。

### S9 无障碍

- 凡定义 `:hover` 的样式块**必须**定义 `:focus-visible`（可守卫）。
- 对话框：`role="dialog"`、焦点约束、Escape 关闭（沿用 `accessible-dialog-model`）。
- 异步结果用 `aria-live`（polite；错误用 assertive 且只用于真错误）。
- 对比度：正文 ≥4.5:1，大字号 ≥3:1；深浅两面分别定义语义色（现状是上下文覆盖，`styles.css:152-163`）。

### S10 规模与性能

- 列表：服务端分页 + 每页档位（16/24/32/48/64/96，沿用现有资产页配置）；超阈值虚拟化。
- 画布：沿用 `LINEAGE_NODE_RENDER_LIMIT`（活动窗口渲染上限）与视口裁剪，不得因改版取消。
- 图片：列表/网格一律用缩略 URL（`asset-thumbnail-url.mjs`），原图只在检查器/放大层加载。

## 5. 规范（Specs，每个区域只有一个写法）

### 5.1 外壳 `AppShell`

```
<AppShell>
  <Rail/>                      240（窄屏 → 顶部横条 / 收起 72）
  <TopBar/>                    56
  <StatusSlot/>                ≤44，0 或 1 条
  <main>{page}</main>          唯一滚动容器

  <Aside/>                     380（覆盖式抽屉，可折叠）
  <DialogLayer/>               40 层
</AppShell>
```

### 5.2 顶栏与面包屑

- 左：品牌（收起态只留标记）+ 面包屑 `项目 ▾ › 任务 ▾ › 批次 ▾`（只读路径 + 点开切换，**不常驻 select**）。
  ⚠️ **2026-09-20 刀哥定（S28）**：面包屑**与标题、搜索框同一行**（`head / ctx / actions` 三条名网格，中间那条吃剩余宽度、
  可以缩到省略号），不再独占 36px 一行——画布这类工作区白丢 42px。**窄档（≤1280）**中间列不足 ~380px，
  面包屑回到自己的独立一行（`"head actions" / "ctx ctx"`），三段名字不许被切碎。
- 右：刷新、（仅运行时）运行指示点、**「出完了叫我」的未读（指示点 + 标题计数，I7）**。
  它是第 1 批 C5 已实现的能力（`completion-notice-model` + `document.title`），批 B 换顶栏时**不许丢**。
  ⚠️ **2026-09-19 审计修正**：原文写「全局搜索」——**现在没有这个东西**（搜索在画布搜索条与资产页内），
  把它放进顶栏属于**新能力**，与 §1「不做新动作」冲突。真要加，先按 §9.3 单独走「标准变更」，不在本方案里顺手加。
- **不放动作**（新建/任务列表/导出一律离开这一行）。

### 5.3 rail 与入口去重

三区：**工作区**（项目管理 / 创作平台 / 资产管理 / 资产交付）→ **资料**（规则资料 / 共享素材 / 创作手册）→ **状态**（生成服务 / 运行状态 / 疑难处理合并为一张状态卡 + 一个疑难入口）。一张状态卡 = 一行结论 + 点开两条明细 + 疑难入口。

**去重对照表**（D2/D4 已拍板后的目标态）：

| 目的地 | 现状入口 | 目标 |
|---|---|---|
| 创作平台 | rail ＋ 上下文条页签 ＋ …（源码里 `view:'lineage'` 15 处） | **rail 一处** ＋ 画布内动作（选中节点后浮现） |
| 资产管理 | rail ＋ 上下文条页签 ＋ 项目概览按钮 ＋ 选片条 | **rail 一处**（保留一级，D2）＋ 项目页「全部资产」一处；**退出上下文条** |
| 生成历史 | 上下文条页签（需先选批次） | **批次检查器内的页签**（同一批次的一面） |
| 计划 | 上下文条页签 | **批次检查器内的页签**（确认闸门也在这里） |
| 批次对比 | 上下文条页签 | **画布上的动作**（选中 ≥2 批次 → 工具条出现「对比」），依据宪法 §4.3 |
| 任务列表 | 上下文条按钮 ＋ 项目概览「全部任务」 | 项目壳的「任务」页签一处；画布上任务节点即入口 |
| 项目概览 | 项目列表里的按钮 | 与「任务」合并为项目壳的两个页签（**D4 已通过**），旧深链保留为归一化别名 |
| **请求队列** | 常驻横贯在内容之上（`request-dock`，占 ~89px 且把画布推下去） | **底部槽唯一常显的 composer**（D1）：idle ≤48、展开 ≤320/35% 且让位；展开层与选片条**同一时刻只一个**（G6，I1） |
| **交付（拿出去）** | 交付页内发起 ＋ 选片条「去交付」＋ 画布节点菜单 | **发起挂在「选中」上**（画布/资产/检查器）；**交付页是一级入口，只做记录与领取**（宪法 §7.11.2） |

**改造后的上下文条只剩面包屑**（§5.2），不再承载导航；同屏可切换的层级控件 ≤1（默认是「批次」），其余以只读段呈现、点开才成菜单。

### 5.4 页面模板 `PageFrame`

```
PageFrame(layout)
├ PageHeader   标题(20) + 说明(12) + 右侧动作(≤2 个)      ≤88
├ PageToolbar  筛选 / 视图选项 / 计数 / 分页               48
└ 内容（主区）
```

- 页面不得自定宽度、不得自造页头、不得在标题区放导航。

### 5.5 工具条

- 48px 单行；左「怎么看」（视角/筛选/搜索），右**只放页面级创建**（新建/导入）。
  ⚠️ **2026-09-19 审计改（I4 / 宪法 §4.4）**：原写右侧放「批量动作」——**批量动作有作用对象**，
  按 §4.4 判据该去**选中后浮现的浮条**（与右键同内容），不是常驻工具条。工具条只回答「怎么看」。
- **危险动作必须视觉区分**。
- 溢出门槛：可见按钮 ≤7。

### 5.6 列表 `DataList`

行式（项目/任务/批次/交付历史）；列不超过 5；主信息一列加粗，次信息一列灰；行尾固定「打开」语义；超过一页用 `PageToolbar` 的分页。

### 5.7 媒体网格 `MediaGrid`

- 卡片：图 + 一行标题 + 状态点；选择控件在左上、动作在右上（沿用现状，但统一到同一组件）。
- 网格列数由 `auto-fill minmax(220px,1fr)` 决定，**不写死列数**（现状逐页写死 2/3/4 列）。
- 放大层：单图/对比（2–4 张）、缩放 0.75×–4×、键盘 ←/→/空格/X/Enter/Esc。
- **放大层必须保留「用这张 / 这组继续」**（现状已有，I2）：挑完就地接下一步——否则人会退出去再找入口。

### 5.8 检查器 `Aside`

三段固定顺序：**它是什么**（属性）→ **过程资产**（计划 / 生成历史，页签）→ **动作**（确认 / 衍生 / 交付 / 重试）。批次、资产、队列全量共用这一个 `Aside`。
- **过程资产段必须保留第 4 批的两样**：计划**「理解说明」一行**（有就显示、没有不显示）与**「存为我的配方」**按钮；
  它们不是装饰——前者是确认前的判断依据，后者是用户侧唯一的复用入口，拆分时不许丢。
- 顶部固定放这一批的四项指标（原 `lineage-focus-strip` 的内容，批 C5 迁入）。
- **就地优先（I5）**：批次节点上的运行控制（暂停 / 取消 / 重试这 N 张）是**第一入口**；
  检查器里的同名动作是**第二条路**——收敛时不许把节点上的控制收进检查器（那是「跳页」的一种）。

### 5.9 底部槽 `BottomSlot`

- idle：一行「说一句」+ 发起 + agent 状态 + 待接数。
- **常显的第二行起**（第 2/3/4 批陆续加的，收敛时一个都不能丢）：
  ① agent 在场/最后活动时间；② **生成服务的运行时提示**（限流/退避，来自 `providerRuntimeNotice`）；
  ③ 队列催促（不在场 / 被领过没完成 / 积压）；④ **「连接与唤起」折叠区**（侦查结果 + 唤起命令 + 催促超时）。
  → ②③ 同一时刻只允许一条（它们说的是同一件事：现在为什么慢）；④ 默认折叠、不占高度。
- 有卡片：向上展开 ≤3 张；**卡片自带回执行 + 就这么出 / 改一下**（第 4 批）——回执行默认显示前 2 行，
  点「展开」看全；「全部记录」开 `Aside`。
- **composer 永不消失（I1，2026-09-19 审计改）**：原写「与选片条互斥」——那会造成
  「手边有图、却没法说一句」的死角，而「选中 + 说一句」正是编排的主路径。改为：
  **常显 composer（idle 48）；选片条与请求卡片共享它上方的展开层，同一时刻只展开一个**（G6 同步改）。
- **三种形态都要能就地读完并回答（I8）**：等待 / agent 正在理解 / 需要你（追问就地答）/ 就绪（就这么出 · 改一下）——
  不许只给「去看全部记录」。
- 展开时必须让内容让位（高度预算见 S1 第 5 条）。

### 5.10 对话框与抽屉

只有两类覆盖层：`Dialog`（需要决策/输入，居中，`z-dialog`）与 `Drawer`（辅助内容，右滑，`z-drawer`）。**不许自造第三种**（现状 shell 末尾挂了 8 个条件浮层与多个对话框，收敛到这两类）。
- **点名归属（2026-09-19 审计补）**：① 确认闸门（`Dialog`，cookie-only 不变）；② 计划编辑（`Dialog`）；
  ③ 轻量遮罩准备（`Dialog`）；④ 新建任务 / 新建批次（`Dialog`，**含「改一下」的目的问卷与配方 chips**）。
  四类各归一类覆盖层，行为不变；**它们的入口一个都不许少**（红线：能力只加强不删）。

### 5.11 空态 / 加载 / 错误

- 空态：一句原因 + 一个动作（无数据 → 「新建/导入」；搜索无果 → 「换个词」；筛选无果 → 「清除筛选」）。
- 加载：骨架屏优先于转圈（列表/网格），转圈只用于按钮内联。
- 错误：人话 + 下一步 +（可选）技术详情（沿用 `AdvancedDetailsPanel` 的下沉层）。

### 5.12 键盘与焦点

`Tab` 顺序 = 视觉顺序；`Esc` 关闭最上层；`/` 或 `⌘K` 聚焦搜索；队列输入 `⌘/Ctrl+Enter` 发送；挑图 ←/→/空格/X/Enter；画布方向键微调（编辑模式）。所有快捷键在「创作手册」里列一张表并由守卫对齐（新增快捷键必须同时进手册）。

## 6. 模块化与分子化（L0–L6）

### 6.1 六层与依赖方向

```
L6 app/          应用壳：路由、数据、SSE、鉴权门、错误边界          （可依赖下面任何层）
L5 views/        页面：一个 view 一个文件，只用模板 + 组织件
L4 templates/    模板：PageFrame、ShellFrame、AsideFrame
L3 organisms/    组织：DataList、MediaGrid、Inspector、CanvasStage、QueuePanel、DeliveryFlow
L2 components/   分子：PageHeader、PageToolbar、RailStatusCard、StatusStrip、EmptyState、RequestCard
L1 primitives/   原子：Button、IconButton、StatusPill、Field、Segmented、Checkbox、Tooltip
L0 tokens/       设计 token：颜色/字号/间距/圆角/阴影/层级/动效（唯一允许字面量处）
```

**依赖只能向下**（L5 可用 L4/L3/L2/L1/L0；L1 不得 import L2 以上）。反向依赖由守卫拦截（§8.3 G7）。

### 6.2 目录与命名

```
web/src/
  tokens/        tokens.css
  primitives/    Button.jsx  StatusPill.jsx  Field.jsx  Segmented.jsx
  components/    PageHeader.jsx  PageToolbar.jsx  RailStatusCard.jsx
  organisms/     DataList.jsx  MediaGrid.jsx  Inspector.jsx  QueuePanel.jsx
  templates/     PageFrame.jsx  ShellFrame.jsx
  views/         ProjectsView.jsx  CreatorWorkbench.jsx  AssetsView.jsx  …
  app/           router.mjs  data/  events/  guards.jsx  App.jsx
  styles/        base.css  primitives.css  components.css  organisms.css  templates.css  surfaces/*.css
```

- 文件 `PascalCase.jsx`（组件）/ `kebab-case.mjs`（模型与纯逻辑，沿用现状）。
- **CSS 归属**：每个组件一个 CSS 块，块名 = 组件名（`.page-header`），`__element` 表内部结构，`--variant` 表变体；**一个 CSS 文件不得选择自己块以外的类**（例外只有 token 与全局工具类）。这条把「覆盖式补丁」从根上堵死。
- 模型与视图分离：可纯函数化的判断（状态映射、预算计算、可访问性）放 `*.mjs`，与现有 `*-model.mjs` 惯例一致。

### 6.3 组件契约（每个组件必须声明）

| 项 | 要求 |
|---|---|
| props | 只收数据与回调，不收「上下文对象」（现状有巨型 props 列表，v2 逐步收敛） |
| 状态 | 必须覆盖 `default / hover / active / focus-visible / disabled / loading`（有异步时加 `error`） |
| 变体 | 变体用 `data-variant` 或修饰类，**不得用行内样式** |
| 尺寸 | 只允许 token 尺寸；不得在组件里写裸 px |
| 文案 | 组件不硬编码业务文案（除纯结构性文案），文案来自调用方或术语单 |
| **结构钩子** | 对外稳定的是 `data-region` / `data-block` / `data-layout` 三个属性，**测试与审计只许断言这些钩子，不许断言 class**（现状有 20+ 个测试断言 `className="…"` 字面量，是本仓最脆的一层；收口见 §8.3 G13） |

### 6.4 准入与上限

- 新组件准入十问（§9）通过才允许进 `components/` 或以上层。
- 行数上限：`primitives` ≤150、`components` ≤250、`organisms` ≤400、`views` ≤400、入口 `App` ≤250。
- 每个 organism 必须有：空态、加载态、错误态、窄屏行为四条声明（可在文档注释里）。
