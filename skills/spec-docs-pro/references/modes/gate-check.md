# 模式：版本门禁检查

适用：判断某个版本能否进入开发，或能否发布。

## 步骤

1. **自动检查。** 运行 `node <skill>/scripts/check-docs.mjs --docs docs --json`，把结果按 `assets/templates/version-gate.md` 中 G01～G12 的“自动检查”列归类。
2. **人工检查。** 没有自动规则的门禁项（G01 范围、G07 接口、G08 数据、G10 追踪）逐项读文档核对，每项给出证据位置（文件 + 章节），不能只打勾。
3. **结论。** 任一门禁项未通过即为 Not Ready。按“阻塞开发 → 可并行补齐”排序列出问题，每个问题写明位置、处理建议和预计工作量。
4. **记录。** 在 `02-产品与版本/版本进入开发门禁.md` 的“检查记录”追加本次结果（日期、命令、错误 / 警告数、结论、未通过项）。
5. **询问下一步。** 问用户是否需要帮忙补齐，不要自动开始修改。

## 判定口径

- 门禁是文档完整性和一致性检查，不评价代码质量。
- 警告不自动阻塞门禁；但同一门禁项下的警告未处理也没有说明理由时，判为未通过。
- 用户刻意不采用某项（例如小项目不写 E2E），记录在门禁文档中并说明理由，视为通过。
