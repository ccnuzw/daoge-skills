# 功能开发流程

本文档是功能规划、实现、测试、验收和文档回写的统一入口。目标是让开发者或 AI 读取有限、明确且无冲突的上下文，得到与产品范围、接口、数据、错误码和当前代码一致的结果。

## 1. 核心原则

1. **版本定范围，功能定行为**：版本文档决定“做不做”，功能主文档决定“怎么做、如何验收”，公共架构决定跨功能约束，代码与测试决定“实际做到什么”。
2. **一个功能一个可独立验收目标**：能回答谁用、输入、成功输出、稳定失败、读写数据、如何独立证明。
3. **三类事实分开**：冻结需求记录在功能文档；实现状态只记录在版本实现状态；待修差距与验证证据记录在实现与验证章节。不得用代码反改需求，也不得用文档冒充实现。
4. **冲突先决策后实现**：字段、默认值、枚举、错误码、状态机、删除、幂等、并发、资金口径不一致时，先写[冻结决策](../06-决策记录/{{活跃版本}}-冻结决策.md)，再同步文档、契约、代码、测试。
5. **小范围、可验证、完整闭环**：一次只处理一个功能或一个明确变更，覆盖业务、前端、接口、数据、错误码、测试、文档和状态。
6. **模板不是业务事实**：模板只定义最低检查范围；未确认差异必须标记负责人与阻塞阶段，影响接口/数据/权限/资金/删除/幂等/验收的差异在 Ready 前清零。

## 3. 功能拆分规则

适合作为单个功能：有清晰角色、输入、输出和验收结果的目标。

- 应继续拆分：多个角色或多个可独立上线目标；混合在线接口与后台任务/通知/导出/运维；数据跨域但无共同事务目标。
- 不应拆分：单个按钮、视觉组件、同一状态机内部步骤；无法独立验收；拆分后无法表达业务价值。

7. 目标功能主文档、[功能风险分级]({{活跃版本}}/功能风险分级.md)与独立技术设计（如有）。

## 5. 标准开发流程

### 阶段 A 确定边界

输出目标版本、功能编号、主文档、本次目标、不做范围、受影响端和业务差异清单。跨功能变更列出所有受影响功能并指定主功能。

### 阶段 B 核对文档与代码

| 项目 | 核对内容 |
| --- | --- |
| 页面 | 路由、字段、列表、状态、操作 |
| 接口 | 路径、方法、鉴权、请求、响应、错误 |
| 数据 | 表、字段、默认值、约束、状态、外键、事务 |
| 安全 | 密钥、Token、权限、审计、日志 |
| 测试 | 单元、集成、前端、E2E 与已有证据 |

输出“已满足、部分满足、未实现、存在冲突”四类结果。

### 阶段 C 冻结冲突

列出冲突文档与代码证据；没有决策时形成选择、影响、迁移方案，写入冻结决策并同步受影响文档。

### 阶段 D 生成任务书

```yaml
version: {{活跃版本}}
feature_id: {{活跃版本}}-FR-001
  feature_doc: {{文档目录}}/03-功能规格/{{活跃版本}}/01-领域/01-功能主文档.md
objective: <本次目标>
in_scope:
  - <包含项>
out_of_scope:
  - <排除项>
decisions:
  - D001
affected_code:
  - <代码目录>
acceptance:
  - AC01
verification:
  - <测试命令>
```

任务书是本次修改的授权边界。

### 阶段 E 实现

推荐顺序：migration 与约束 → 领域规则 → 事务与服务 → HTTP 与错误 → 前端类型 → 页面交互 → 单元/集成测试 → E2E → 文档与状态。

必须遵守：业务校验不能只放前端；唯一性、幂等和资金安全由数据库约束兜底；金额用 Decimal；时间存 UTC；路由隐藏不能代替服务端权限；敏感字段不进入日志、错误、列表或导出。

### 阶段 F 验证与回写

至少完成与风险相称的单元、数据库事务、接口错误矩阵、页面状态、关联 E2E 和文档检查。完成后更新：

- 功能主文档“实现与验证”章节。
- [{{活跃版本}} 实现状态](../02-产品与版本/当前版本/{{活跃版本}}-实现状态.md)。
- 追踪矩阵（接口、数据或 E2E 映射变化时）。
- 公共接口、数据或错误码文档（公共契约变化时）。
- 端到端或发布证据（实际执行时）。

## 6. 变更联动

| 变更类型 | 必须同步 |
| --- | --- |
| 新增或修改接口 | 功能接口章节、公共接口契约、OpenAPI、前端类型、接口测试 |
| 新增或修改字段 | 功能接口/数据章节、数据模型、migration、序列化类型 |
| 新增错误码 | 功能错误矩阵、统一错误码、后端映射、前端提示、错误测试 |
| 页面交互变化 | 功能需求章节、界面规范（公共变化时）、前端测试 |
| 状态机变化 | 功能需求/数据章节、事务测试、E2E |
| 删除行为变化 | 依赖保护、接口、外键策略、确认交互、回归测试 |
| 权限变化 | 接口鉴权、页面守卫、越权测试、审计 |
| 资金逻辑变化 | 决策、数据事务、幂等、流水、并发测试、E2E、发布门禁 |
| 完成度变化 | 功能验证记录、版本实现状态 |

## 7. Definition of Ready

- 目标版本、稳定功能 ID、主文档已确定。
- 用户故事、范围、不做范围清晰；页面字段或系统输入已冻结。
- 接口请求、响应、鉴权、错误已冻结。
- 数据字段、状态、事务、幂等、删除行为已冻结。
- 文档冲突已进入冻结决策；依赖功能状态支持开发。
- AC 覆盖正常、错误、权限、重复、并发、回滚，并映射测试层级、目标资产、命令和证据状态。
- 已核对代码差距；高风险功能完成独立设计与分支映射。
- 接口变化已同步机器可读契约。

未满足时保持“规划中”，不进入编码。

## 8. Definition of Done

- 后端业务与服务端校验完成；前端交互完成或明确不适用。
- migration、约束和事务完成。
- 接口与错误符合冻结契约。
- 单元、集成、前端测试通过；关联 E2E 通过。
- 日志、权限、敏感信息检查通过。
- 功能主文档、公共文档、实现状态同步。
- 验证记录含日期、环境、构建标识、命令和结果。
- 涉及真实支付、缓存或生产运维时具有相应环境证据。

## 9. 可复用提示词

### 开发已有功能

```text
请按照 {{文档目录}}/03-功能规格/功能开发流程.md 开发：

版本：{{活跃版本}}
功能文档：<中文功能主文档路径>
本次目标：<明确目标>

完整读取功能主文档、技术设计（如有）、公共契约、实现状态和相关代码。
先输出差距检查和任务边界；冲突先形成冻结决策。
完成实现、测试、文档和状态回写，并给出可复现验证证据。
```

### 新增功能

```text
请按照 {{文档目录}}/03-功能规格/功能开发流程.md，为 <版本> 新增功能：<功能名>。

先判断是否可独立验收并分配稳定编号；在功能索引和查找表登记。
创建章节完整的中文主文档；高风险功能另建技术设计。
同步公共接口、数据、错误码、追踪和 E2E，输出 Ready 检查结果。
未 Ready 时不写生产业务代码。
```

### 只做实现核查

```text
请按照 {{文档目录}}/03-功能规格/功能开发流程.md 核查 <功能主文档>，不要修改代码。

对照需求、接口、数据、错误、页面、测试和当前代码，输出：
已满足、部分满足、未实现、文档/代码冲突、风险优先级和推荐顺序。
所有结论提供具体文档或代码证据。
```

## 10. 禁止做法

- 只读产品总览，不读目标功能和当前代码。
- 只生成目录和通用段落，不写字段、错误和状态。
- 以当前代码默认值覆盖冻结需求而不记录决策。
- 只改后端，不同步前端类型、页面和契约。
- 只靠前端限制权限或字段；捕获数据库错误后统一返回 500。
- 使用浮点计算金额；日志输出完整 Key、Token、支付密钥或签名 URL。
- 把规划命令、本地 mock 或静态核验写成生产验证通过。
