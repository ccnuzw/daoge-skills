# 渐进式 SDD：边写规格边开发

本指南定义文档尚未全部完成时，如何安全地开始一个**明确的交付切片**。它补足全局版本门禁与单功能 Ready 之间的空档，不降低单一权威来源、稳定追踪和证据真实性要求。

## 1. 三种范围

| 范围 | 目的 | 允许进入开发的条件 |
| --- | --- | --- |
| 版本 | 决定本版做什么、不做什么和成功标准 | 版本范围、依赖、关键约束和风险已冻结 |
| 交付切片 | 一次可独立实现、验证和回写的功能或跨功能目标 | 关联功能达到 Ready，切片边界和依赖明确 |
| 功能 | 描述一个可独立验收目标的行为 | 功能文档、契约、数据、AC 和测试映射达到 Ready |

版本可以分阶段解锁（例如 `V1-P1`），但每个解锁阶段都必须明确交付切片、依赖、排除项和验收入口。没有达到版本门禁的部分只能继续做调研和规格工作。

## 2. 推荐状态

### 规格状态

- `Draft`：仍有会改变实现输入的未决项。
- `Ready`：本切片的行为、契约、数据边界、AC 和验证入口足够开始实现。
- `Frozen`：本切片已进入实现，修改需要走变更联动和决策记录。

### 实现状态

实现状态仍只维护在版本实现状态表。规格状态与实现状态不能合并，也不能用“已实现”替代验收证据。

## 3. 切片开工条件

一个切片可以在其他功能仍为 Draft 时开工，只要满足：

1. 版本范围已覆盖该切片，且 `delivery_scope=active`。
2. 本切片和直接依赖的功能有稳定 ID 与来源追踪。
3. 影响本切片的接口、数据、错误、权限和状态机口径已冻结；未决项有负责人、截止点和阻塞范围。
4. 每条本版 AC 都有 Given/When/Then、失败无副作用断言和测试映射；测试可以处于规划状态。
5. 真实外部依赖、生产证据或后续切片不能被写成当前切片已完成。

未决项只阻塞受影响的切片。资金、权限、秘密、删除、外部回调和跨系统状态的未决项，默认阻塞整个受影响切片。

## 4. 开发循环

每个切片重复以下循环：

1. `Draft → Ready`：补齐规格和映射，运行 `review-docs --phase planning --feature <id>`。
2. `Ready → Frozen`：登记开始实现的切片、负责人和变更基线。
3. 实现并执行目标测试；只把真实结果写入证据空间。
4. 回写功能验证章节和版本实现状态，运行 `review-docs --phase development --feature <id>`。
5. 跨功能目标进入 E2E/发布空间后，再运行全局 `docs-gate`。

局部审查通过只表示该功能或切片的输入完整，不表示整个版本或发布已就绪。全局门禁仍必须在版本解锁和发布时运行。

## 5. 变更规则

- 只改变本切片且不改变公共契约的文档修改，可以在功能文档中完成并记录变更。
- 改变接口、字段、状态、错误、权限、资金或跨功能终态，必须先写冻结决策，再同步公共契约、代码、测试和追踪矩阵。
- 新增未来能力时使用 `delivery_scope=future` 或 `planning_only=true`，不得进入当前实现状态和交付统计。
- 切片完成后必须保留“本次交付范围、证据等级、遗留风险和后续切片”记录。

## 6. 何时不能并行

以下情况不能以“先实现、后补文档”推进：公共字段或枚举尚未定稿、权限边界不明确、资金/删除/幂等语义冲突、跨系统状态没有所有者、或失败时副作用无法断言。此时先冻结决策或缩小切片。
