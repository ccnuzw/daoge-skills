# 模式：把现有文档升级到当前标准

适用：项目已有 `docs/`，但用的是旧写法（AC 写成表格、frontmatter 不全、状态词不标准、文件序号和功能编号对不上）。用脚本做，不要为每个项目现写一次性脚本。

## 步骤

1. **先检查。** `node <skill>/scripts/check-docs.mjs --docs <docs路径>`，记下基线（AC008、ID002、ID003、ST002、ST004、AC009 是迁移能解决的）。
2. **预演。** `node <skill>/scripts/migrate-docs.mjs --docs <docs路径>`。默认只打印 diff 和需要人工处理的事项，不写任何文件。把 diff 给用户过目。
3. **写入。** 用户确认后加 `--write`。写入前脚本会校验：每条 AC 的编号转换前后一致，每个单元格的原文都还在转换后的文本里；任何一项失败就不写，退出码为 1。
4. **处理人工事项。** 脚本不猜的内容（含糊的状态词、没有拆出 Given / When / Then 的 AC、文字里提到的旧文件名）列在输出末尾，逐条改。
5. **再检查，重新生成浏览器。** 迁移后重新运行 check-docs；`generate-browser.mjs` 之后用 `--check` 确认产物是最新的。

## 脚本做什么

| 步骤（`--only`） | 做什么 | 不做什么 |
| --- | --- | --- |
| `frontmatter` | 补缺的 `feature_id`、`version`、`domain`、`spec_status`（值来自功能卡、文件序号、目录名）；实现状态表已记录该功能时，删除旧的 frontmatter `status` 和功能卡“状态”行 | 实现状态表里没有记录时不删，改为提示 |
| `ac-table` | 验收标准表格 → `#### ACNN 标题` + Given / When / Then；识别“前置 / 操作 / 预期”等列名；其他列变成 `- 列名：内容` | 不改写、不合并、不翻译单元格原文；表里有非 AC 编号的行时整张表不转换 |
| `status` | 实现状态、证据状态里整格等于别名的词改成标准词（设计中 → 规划中；已通过 → 本地通过） | 不从长句里猜状态；“后端通过”这类没有环境信息的词只提示 |
| `renumber` | 文件序号改成与功能编号一致（技术设计一并改），并改写所有指向它们的链接，锚点保留 | 不改文字里的文件名；目标文件已存在时不改名，只提示 |

`--only ac-table,status` 可以只跑部分步骤。迁移是幂等的：再运行一次应当没有新改动。

## 状态词怎么选

脚本不知道 AC 是否全部通过，所以含糊的状态词只给“AC 证据最多支持哪个状态”。选词按 [status-update.md](status-update.md) 的判定表，不按进度描述。
