# {{VERSION}} 性能测试执行手册

## 执行前检查

1. 生成 `run_id`，锁定 commit/build/image/migration、工具版本和 Profile 摘要。
2. 确认 Profile 已批准，或明确标记 `local-smoke`/`calibration`，禁止混用结论。
3. 验证压测机、服务、数据库、缓存、模拟器的时钟、ready 和资源余量。
4. 建立专用租户和夹具，记录余额、用量、消费、Hold、请求计数和资源基线。
5. 预热连接池、缓存、Driver 和指标采集；预热样本不进入正式聚合。

## 监控与停止条件

持续观察延迟、错误分类、容量拒绝、CPU、RSS、队列、连接池、上游请求、Platform 请求和账务异常。出现资金/数据不变量、敏感信息、服务不 ready、无界增长或生成器受限时立即停止增加负载并保存原始证据。

## 结果分析

- 逐请求计算指标后聚合，不用不同分位数相减。
- `expected_capacity_rejection`、`expected_business_rejection` 和 `unexpected_error` 分开统计。
- 分析稳态区间、峰值边界、恢复窗口、资源趋势和数据库池。
- 对唯一 `run_id + request_id` 核对用量、消费、Hold、余额、幂等和外部调用次数。
- 失败批次使用新 run_id 重跑，不能覆盖原始报告。

## 证据保存

记录 Profile ID、负载摘要、环境指纹、工具版本、命令与退出码、原始指标引用、聚合结果、截图/日志脱敏位置、失败/跳过和残余风险。

## 环境恢复

停止负载并采集批准恢复窗口；清理当前 run_id 夹具和临时权限；撤销测试秘密；确认没有残留队列、租约、外部请求或共享租户影响。
