# 机器可读证据报告规范

本文件定义交付证据的通用契约，不保存业务规则。

## 两层检查

| 层 | 命令 | 回答 | 通过意味着 |
| --- | --- | --- | --- |
| 结构层 | `node scripts/check-docs.mjs` | 文档体系是否自洽（目录、链接、编号、索引、AC 列） | 可以继续工作 |
| 交付层 | `node scripts/docs-gate.mjs` | 当前构建是否具备完整、未过期、相互绑定的证据 | 可以交付 |

结构检查通过**不代表**交付就绪；`docs-gate` 缺证据时失败是预期行为，不得通过填写虚构报告消除阻塞。

## 配置文件

| 文件 | 作用 |
| --- | --- |
| `docs-policy.json` | 结构策略：活动版本、必需文件、ID 规则、功能文档目录 |
| `docs-gate.json` | 门禁策略：权威文档清单、必需报告、审批角色、环境白名单、命令登记、秘密扫描 |
| `docs-evidence.json` | 当前证据指针：commit、审批、四类报告路径与环境 |
| `<报告名>-manifest.json` | 批次运行清单：code_version、command、exit_code、asset_sha256、sanitization、limitations |

## 报告类型

可用 `node scripts/docs-gate.mjs --scaffold-report dev|e2e|perf|release` 生成符合契约的空报告与 manifest 模板；模板不含任何通过结论，填写实际执行结果后才可作为证据。

### 开发环境

干净检出状态、依赖模式、实际命令与退出码、服务地址、HTTP 状态与就绪结果；门禁重算退出码与状态。

### E2E

环境、依赖模式、规范命令、逐用例状态或统计；跳过或失败不能产生通过结果；必须能映射到用例矩阵。

### 性能

已批准的负载配置（id/sha256/批准人/时间）与逐场景 `metric/comparator/threshold/measured`；门禁重算比较符，不信任手填结论。

### 发布

精确制品标识、当前 E2E/性能报告路径、migration、备份、恢复、安全、冒烟、观察、回滚与角色审批；必须绑定当前提交。

## 审批与摘要

```sh
node scripts/docs-gate.mjs --authority-digest
```

- 摘要由权威文档（`docs-gate.json` 的 `authorityFiles`）逐文件哈希拼接而成。
- 审批记录提案 ID、确认人、确认时间与摘要；权威文档变化后原审批自动失效。
- 确认必须发生在完整提案展示之后，不能预先填写或由脚本自行批准。

## 证据边界

- 报告与 manifest 必须在仓库内，放入端到端验收的 `报告/` 目录，只追加不覆盖。
- 不得包含密钥、令牌、签名 URL、完整请求内容或未脱敏数据；门禁有启发式秘密扫描。
- 失败批次不可被后续成功批次覆盖；不同环境证据不可互换。
- 不得为使门禁通过而伪造审批、时间、提交、制品、执行结果或剩余门禁。
