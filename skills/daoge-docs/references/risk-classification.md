# 功能风险分级

## 设计前先分级

逐项检查以下信号：

| 风险信号 | 示例 |
| --- | --- |
| 权限 | 角色边界、数据所有权、委托访问、管理员能力 |
| 秘密 | 密码、API Key、加密、Token、签名材料 |
| 资金 | 余额、价格、扣费、退款、结算、财务导出 |
| 并发 | 锁、配额、重复请求、竞争状态转换 |
| 外部副作用 | 支付、Webhook、第三方调用、邮件、文件 |
| 动态制品 | 插件、脚本、Driver、上传的 Schema |
| 跨系统状态 | Saga、最终一致性、对账、补偿 |
| 破坏性生命周期 | 删除、恢复、保留、迁移、匿名化 |
| 生产门禁 | 容量、恢复、合规、安全发布条件 |

## 标准风险

只有行为局部封闭，且失败不会破坏资金、权限、秘密或跨系统事实时，才使用 `standard`。技术设计可以放在功能主文档内，但仍要写明入口、重要分支、不变量、数据副作用、失败语义和测试映射。

## 高风险

任一风险信号具有实质影响，或功能组合多个领域与副作用时使用 `high`，并建立独立技术设计。设计至少包含：

1. 入口签名、调用方和所有者。
2. 前置条件、后置条件和业务不变量。
3. 数据库约束、事务和锁边界。
4. 稳定分支 ID 和完整决策表。
5. 幂等键、唯一约束和重复请求语义。
6. 外部调用顺序、超时、可重试分类和未知结果。
7. 补偿、对账和人工修复路径。
8. 权限、秘密、隐私和敏感日志边界。
9. 观测指标、告警和操作控制。
10. 迁移、兼容、灰度、回滚和恢复。
11. 分支到 AC、集成/E2E 和发布门禁的映射。

## 升级规则

标准风险功能出现资金字段、权限扩大、外部副作用、异步任务、跨服务写入、并发竞争、动态配置或破坏性迁移时，必须先升级风险并补独立设计。不得因为实现已经开始而维持较低分级。
