# {{活跃版本}} E2E 环境规范

## 1. 环境类型

| 环境 | 用途 | 可证明范围 | 不可替代 |
| --- | --- | --- | --- |
| `local` / `local-mock` | 日常回归、外部依赖模拟 | 业务状态机、错误码、幂等、数据关联 | 真实外部依赖、生产故障策略与发布门禁 |
| `staging` | 联调和候选版本验收 | 真实部署拓扑、密钥挂载、网络与回调 | 最终生产发布签字 |
| `production-gate` | 发布前门禁 | 真实外部依赖、轮换、备份恢复和故障策略 | 不适用 |

执行记录必须填写环境类型，不得只写“已通过”。

## 2. 本地拓扑

| 组件 | 地址 | 用途 |
| --- | --- | --- |
| <服务名> | `http://127.0.0.1:<port>` | <职责> |
| <数据库> | `127.0.0.1:<port>/<db>` | 业务数据与断言 |
| <缓存> | `127.0.0.1:<port>` | <用途> |

<列出启动方式或 docker-compose 路径。>

## 3. 配置要求

- 从示例环境文件创建本地配置，不得把真实密钥提交到仓库。
- 批次内固定的密钥/盐/令牌不得跨批次复用；记录中不得出现私钥内容。
- 外部依赖的模拟模式与真实模式必须显式记录（如 `payment_mode=mock` / `payment_mode=real`）。
- 测试专用开关只能作用于测试环境；development/production 不得接受。

## 4. 就绪检查

执行 E2E 前必须确认：

```text
GET <服务>/health
GET <服务>/ready
```

全部返回成功；失败时停止业务用例，先记录环境故障。

## 5. 隔离与重置

- 每个运行批次使用唯一 `run_id`，建议格式 `<版本>-YYYYMMDD-HHMM-<build>`。
- 动态数据（邮箱、名称、幂等键）包含 `run_id`，避免并行批次冲突。
- 清理只删除本批次创建且明确允许删除的数据；资金和审计记录优先随隔离数据库销毁。
- 禁止在共享环境执行全库清空或删除存储卷；生产门禁不得执行破坏性清理。
