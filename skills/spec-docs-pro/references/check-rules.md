# check-docs 规则说明

`node scripts/check-docs.mjs --docs docs` 只读，不修改文件。错误（✖）阻断门禁，警告（⚠）需要处理或说明理由，提示（ℹ）仅供参考。`99-历史归档/` 下的文档跳过内容检查，但仍参与编号统计。

在 `docs/spec-docs.config.json` 的 `check.ignore` 中可以忽略整类规则（例如项目刻意不用技术设计分支时忽略 `BR002`），忽略要在团队中达成一致。

| 规则 | 级别 | 检查内容 | 修复方式 |
| --- | --- | --- | --- |
| ID001 | 错误 | 功能编号重复 | 保留先分配的编号，后来者分配新编号 |
| ID002 | 警告 | 功能主文档缺少 frontmatter `feature_id` | 补 `feature_id: V1-FR-NNN` |
| ID003 | 警告 | 文件序号与功能编号不一致。消息给出应改成的文件名和引用它的文件清单（`--json` 的 `suggestion.renames` 含完整引用位置） | 改文件名，不改编号；`migrate-docs.mjs --only renumber` 可同时改链接 |
| ID004 | 错误 | 决策或 ADR 编号重复 | 重新编号后来者，并更新引用 |
| REF001 | 警告 | 引用了不存在的功能编号。需求编号文档“保留编号 / 已废弃编号”表里登记的编号（支持 `V1-FR-011～016`）不报 | 修正编号，或先登记该功能，或登记为保留编号 |
| REF002 | 警告 | 引用了不存在的决策编号。保留编号表里登记的不报 | 修正编号，或补记决策 |
| REF003 | 警告 | 保留或已废弃编号表里的编号，却有一份正在使用的功能文档 | 从表中移除，或把该功能标为 Deprecated |
| LNK001 | 错误 | docs/ 内的链接或图片目标不存在 | 修正路径，或补齐目标文件 |
| LNK002 | 警告 | 链接锚点在目标文档中找不到。比较用 GitHub 的算法：小写、保留下划线、去掉其他标点、空格变 `-`，重复标题依次加 `-1`、`-2` | 改为目标标题的锚点 |
| LNK004 | 警告 | 锚点只是某个标题锚点的前缀（`#d007` 对 `d007-局域网-...`）。离线浏览器能跳转，GitHub 不能 | 写完整锚点 |
| LNK003 | 提示 | 链接指向 docs/ 之外且不存在 | 多为仓库代码路径，确认即可 |
| AC001 | 错误 | 功能主文档没有 AC | 按 `#### AC01 标题` + Given/When/Then 补写 |
| AC002 | 错误 | AC 编号重复 | 重新编号后来者 |
| AC003 | 警告 | AC 没有完整的 Given / When / Then | 补齐三段 |
| AC004 | 错误 | 有 AC 但没有“AC 逐项测试设计”表 | 按模板补表 |
| AC005 | 错误 | 某条 AC 不在测试设计表中 | 补一行 |
| AC006 | 警告 | 测试设计缺少测试层级、目标资产或目标命令 | 补齐；暂未确定写“待定：{原因}” |
| AC007 | 警告 | 测试设计表中的 AC 没有定义 | 删除该行或补 AC |
| AC008 | 警告 | AC 用表格简写 | 改为标题 + Given/When/Then |
| AC009 | 警告 | 测试设计表没有“证据状态”列，或该列的值不在词表（未创建 / 已创建 / 静态核验 / 本地通过 / 预发通过 / 生产通过 / 失败 / 不适用）；只有整格等于别名时才给改写建议 | 改为标准词，补充说明放备注列 |
| AC010 | 警告 | 证据状态与资产自相矛盾：写“已创建”及以上，目标资产却是“规划 / 未创建 / 待定”；写“本地通过”及以上，目标命令却是“待定” | 证据不能先于测试资产，改回“未创建”或补齐资产 |
| BR001 | 警告 | 分支 ID 的功能号与所在功能不一致 | 改为 `B{本功能号}-NN` |
| BR002 | 错误/警告 | 伪代码有分支 ID 但缺少追踪表（错误），或某个分支未出现在表中（警告） | 补“分支到测试追踪”表 |
| BR003 | 警告 | 分支追踪表引用了不存在的 AC | 修正 AC 编号 |
| TD001 | 警告 | 高风险功能没有独立技术设计 | 新建 `NN-功能名-技术设计.md` |
| FC001 | 警告 | 功能卡缺少或未填写 领域、规格状态、风险等级、上游依赖（浏览器里会显示空白，缺风险等级会被当成“标准”） | 填写；确实没有写“无”或“不适用：理由” |
| ST001 | 警告 | 功能未出现在实现状态表中 | 在实现状态表补一行 |
| ST002 | 警告 | 功能主文档记录了实现状态 | 删除 frontmatter `status` 与功能卡“状态”行，改用 `spec_status` |
| ST003 | 警告 | 规格状态不在 Draft / Ready / Deprecated 中 | 改为标准词 |
| ST004 | 警告 | 实现状态表“状态”列不是标准词。整格等于别名时给出改写；其余（如“核心实现完成，待正式验收”）不猜，只说明该功能的 AC 证据最多支持哪个状态，按 `modes/status-update.md` 的判定表选词 | 改为标准词，细节移到其他列 |
| ST005 | 警告 | 实现状态表没有单独的“状态”列 | 增加“状态”列 |
| ST007 | 警告 | 实现状态是本地验证 / 待验收 / 已完成，但该功能 AC 测试设计表里仍有证据状态低于“本地通过”或“失败”的行 | 补齐证据，或把状态降回开发中 |
| ST006 | 警告 | 有功能但没有实现状态文档 | 用模板创建 |
| DC001 | 警告 | 决策没有标准状态 | 补 `- 状态：已冻结` 等 |
| EV001 | 警告 | 功能演进矩阵中没有识别到能力主线表格 | 按模板改为“阶段”表格 |
| EV002 | 警告 | 功能未关联能力主线 | 在 frontmatter 写 `track:`，或在配置 `featureTracks` 中映射 |
| EV003 | 警告 | 阶段表少于 5 列 | 补齐列 |
| EV004 | 警告 | 阶段名不以 `V{n}` / `后续` 开头 | 改写阶段名 |
| EV005 | 警告 | 用层级标题描述阶段 | 改为表格行 |
| VR001 | 警告 | 规划中的版本没有独立规划文档 | 创建 `后续版本/V{n}-{主题}.md` |
| TPL001 | 警告 | 残留模板占位符 | 填写或写“不适用：理由” |
| CFG001 | 警告 | `check.ignore` 里有不存在的规则号（会提示相近的规则） | 改正或删除 |
| CFG002 | 警告 | `featureTracks` 映射到不存在的功能，或匹配不到任何能力主线 | 改成演进矩阵里的章节标题 |
| CFG003 | 警告 | 其他配置问题：未知配置项、`profile` 取值无效、`docGoals` / `keyDecisions` / `exclude` 指向不存在的目标 | 改正或删除 |

退出码：0 表示没有错误；1 表示有错误，或警告数超过 `--max-warnings`；2 表示参数错误（含 `--config` 指向不存在的文件）。

## 保留编号

有意提前登记的编号（例如 `V1-FR-011～016` 预留给支付）写在需求编号文档（`V{n}-需求编号.md`）里标题含“保留”或“已废弃”的表中，第一列写编号，范围用 `～`、`~`、`-` 或“至”连接。登记后 REF001 / REF002 不再对这些编号报警，其他写错的编号照常报告。不要为此在 `check.ignore` 里忽略整类 REF001。

## 规模档位（profile）

`spec-docs.config.json` 的 `"profile"` 取 `small` / `medium` / `large`，默认 `medium`。只有 `small` 有区别：规格状态为 Draft 的功能暂不检查 AC001、AC004、AC005、AC006、TD001、FC001，规格改为 Ready 后恢复。其余规则在所有档位下一样执行，包括编号、链接、重复、证据真实性（AC009、AC010、ST007），因为它们守的是硬规则。被豁免的条数会在输出末尾和 `--json` 的 `summary.exempted` 中列出，不会静默消失。

## 配置检查

`check.ignore`、`featureTracks`、`docGoals`、`keyDecisions`、`exclude` 里的拼写错误会报 CFG001～CFG003。
