## 2. 每个功能的最低矩阵

- 正常主流程；必填、格式、上下界与枚举。
- 未登录、错误角色与对象所有权。
- 资源不存在、禁用、过期与依赖冲突。
- 重复提交与幂等；关键写操作并发与事务回滚。
- 日志、错误与响应敏感信息检查。
- 前端加载、空态、失败态与成功反馈。

## 3. 资金功能附加要求

- Decimal 精度与舍入；同一业务键重复调用。
- 并发扣费、补单与退款；任一步失败后全事务回滚。
- 订单、用量、消费、流水与审计关联完整。

## 4. 权限功能附加要求

- 越权矩阵：未登录、错误角色、他人对象、已禁用主体。
- 会话撤销后旧凭证失效；服务端 fail-closed 行为。

## 5. 路由与外部依赖附加要求

- 候选矩阵：启停、额度、健康状态与权重边界。
- 无候选、上游超时、连续失败冷却与半开恢复。
- 并发选择冲突的处理与幂等。

## 6. 性能与容量附加要求

- 使用版本化且已批准的负载配置；没有目标 RPS、并发、数据规模的结果不构成门禁证据。
- 阶梯、稳态、过载与恢复分别留证；预期容量拒绝与非预期错误分开统计。
- 新增可增长列表必须做结构性预检（服务端分页、稳定排序、索引命中）。
- 静态审计与本地单请求延迟只算“性能预检”，不得据此填写吞吐或 p95/p99 结论。

## 7. 验证记录模板

规格基线核验与测试执行记录是两类证据：前者可用“文档 + 静态审计”，后者必须包含实际命令、构建标识与结果。不得用静态核验替代测试通过记录。

```text
验证日期：YYYY-MM-DD
环境：local / staging / production-gate
代码版本：commit 或构建标识
命令/用例：...
结果：通过 / 失败
证据：日志、报告或工单位置
遗留风险：...
```
