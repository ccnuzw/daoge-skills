# Spec-Docs-Pro 快速上手

## 5 分钟快速开始

### 1. 初始化项目文档体系

```
使用 spec-docs-pro 为我的项目初始化文档体系：
- 项目名称：MyProject
- 项目类型：Web应用
- 首个版本：V1
- 核心领域：用户管理、内容管理、支付
```

这会创建完整的 `docs/` 目录结构。

### 2. 创建第一个功能

```
使用 spec-docs-pro 创建功能规格：
- 版本：V1
- 功能名称：用户注册
- 领域：用户管理
- 功能目标：让新用户通过邮箱注册账号
- 包含：邮箱密码注册、邮箱唯一性校验
- 不包含：第三方登录、邮箱验证
```

生成 `docs/03-功能规格/V1/01-用户管理/01-用户注册.md`。

### 3. 记录决策

当遇到冲突时：

```
使用 spec-docs-pro 记录冻结决策：
背景：PRD 未明确密码存储方式
决定：使用 Argon2 哈希存储
影响：功能 01 用户注册
```

记录到 `docs/06-决策记录/V1-冻结决策.md`。

### 4. 生成浏览器

```
使用 spec-docs-pro 生成文档浏览器
```

生成交互式 HTML 界面：`docs/90-参考资料/产品文档浏览器.html`

### 5. 检查门禁

```
使用 spec-docs-pro 检查 V1 版本门禁
```

验证文档完整性，确认是否可以进入开发。

## 常见工作流

### 新项目启动

1. 初始化文档体系
2. 编写版本总览和产品需求
3. 为每个核心功能创建规格文档
4. 建立需求追踪矩阵
5. 通过版本门禁检查
6. 开始开发

### 添加新功能

1. 创建功能规格文档
2. 评估风险，高风险创建技术设计
3. 更新需求追踪矩阵
4. 开发实现
5. 更新实现与验证章节
6. 运行测试并记录证据

### 解决冲突

1. 识别冲突（文档 vs 代码 vs PRD）
2. 记录冻结决策
3. 同步所有受影响文档
4. 更新代码实现
5. 验证一致性

## 核心概念

### 稳定编号
- 一旦分配，终生不变
- 移动文档不改编号
- 废弃功能保留编号，标记状态

### 三类事实分离
- **冻结需求**：版本必须满足的行为
- **当前实现**：代码和测试的实际状态
- **待修差距**：两者之间的差异

### 权威来源
- 同一事实只维护一处
- 其他地方通过链接引用
- 发现冲突先记录决策

### 证据驱动
- 状态变更必须有可复现证据
- 本地验证 ≠ 生产验证
- Mock 不能替代真实证据
