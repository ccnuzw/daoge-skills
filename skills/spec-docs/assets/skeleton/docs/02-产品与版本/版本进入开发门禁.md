# 版本进入开发门禁

本文档约束后续版本从“规划骨架”升级为“可交给研发或 AI 实现”的条件。未来版本只有概要文档是有意设计，不表示已经具备开发输入。

## 当前阶段

| 版本 | 当前阶段 | 是否可直接进入实现 |
| --- | --- | --- |
| {{活跃版本}} | 活跃开发与验收准备 | 仅按功能状态逐项推进 |
| 后续版本 | 规划骨架 | 否；必须先通过本门禁 |

## 进入开发必须全部满足

| 门禁 | 最低产出 | 判定标准 |
| --- | --- | --- |
| 范围冻结 | 版本规划、做/不做、依赖、成功标准 | 与前后版本无重复或隐式前置 |
| 全局约束 | 对全版本约束逐项做适用性检查 | 硬约束未被降级；例外已冻结决策 |
| 稳定编号 | `Vx-FR/NFR/RG` 编号表 | 编号不依赖章节位置，可追踪且不复用 |
| 架构 | 上下文/容器图、关键序列图、状态机 | 模块边界、数据所有权、失败与补偿路径明确 |
| API | Markdown 语义文档 + OpenAPI/JSON Schema | 输入、输出、鉴权、错误、幂等、分页可校验 |
| 数据 | ER/关系、字段约束、索引、迁移、生命周期 | 状态、唯一性、事务、保留策略明确 |
| 功能规格 | 每个可独立验收目标一份主文档 | 不用通用模板句代替真实流程；章节口径一致 |
| 技术设计 | 全功能风险评审；高风险独立设计 | 关键分支有稳定 ID；不需独立设计的有理由 |
| 测试 | Unit/Integration/E2E 分层矩阵 | 分支 ID 映射 AC；E2E 说明真实入口与最终状态 |
| 追踪 | PRD → 功能 → API/数据 → 分支 → AC/E2E | 无孤立必做需求和无来源接口 |
| 安全与发布 | 安全基线、部署、回滚、恢复、证据空间 | 不用本地 mock 代替生产门禁 |
| ADR | 影响架构的决策有背景、备选、理由、后果 | 已知风险与重新评估条件明确 |

## 执行规则

1. 先复制结构，不复制业务结论；每一项按该版本实际风险重新填写。
2. 可以按阶段进入开发（如 V1-P1），但阶段自身必须满足完整门禁并有独立 E2E。
3. 门禁未过时，AI 只能协助调研、质疑和补规格，不得据概要文档批量生成生产实现。
4. 达到 Ready 后在版本总览中记录日期、评审角色、未决风险和证据位置。
5. 影响资金、权限、数据删除、外部回调或跨系统状态的待确认项一律阻止 Ready。
