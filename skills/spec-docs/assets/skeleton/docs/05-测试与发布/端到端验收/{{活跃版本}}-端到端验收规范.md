## E2E 判定标准

- 必须从真实入口触发：使用公开 API 或明确的外部入口，不允许直接调用内部函数代替入口。
- 必须验证最终业务结果：响应、数据库状态、幂等记录、余额/流水、外部调用次数或可观察任务结果，不能只断言 HTTP 200。
- 关键依赖必须真实：数据库、鉴权、路由、资金事务和本系统状态持久化使用真实组件；不得 mock repository/service 后声称 E2E。
- 允许的替身必须显式声明：可控外部替身只验证本系统契约与副作用；真实外部依赖的门禁必须单独使用 production-gate，不能被本地结果替代。
- 每次执行必须在[验证证据](验证证据.md)登记构建标识、环境、依赖模式、命令、结果和脱敏证据。
