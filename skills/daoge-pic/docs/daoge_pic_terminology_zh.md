# daoge-pic 界面术语单（人读版）

> 这份文档与 `web/src/terminology.mjs` 由测试锁一致（条目必须一一对应，改一边不改另一边会 fail）。
> 想改术语，先改模块，再跑 `node scripts/run-tests.js`，然后同步这里。

## 判据

**不是「去英文」，是「分清谁在说话」。** 判据是「属于创作者语汇 vs 系统实现」，不是中英之分。

三级：

| 级别 | 含义 | 处理 |
| --- | --- | --- |
| 保留 | 创作者本来就这么说，或本来就是英文专名 | 原样留 |
| 译好 | 系统实现词，但创作者需要理解 | 给一个自然说法 |
| 收回 | 纯实现细节 | 创作者面禁用；需要时下沉到「技术详情」层 |

## 面向面

一刀切会改坏东西，所以先分面：

| 面 | 范围 | 允许什么 |
| --- | --- | --- |
| creator | 创作者主路径（导航 / 按钮 / 状态 / 空态 / 错误） | 必须人话 |
| config | 技术配置面（生成服务设置） | 允许术语，但必须配人话副标题 + 视觉隔离 |
| doc | 文档面（创作手册正文） | 允许术语，首次出现要给解释 |

分类文件清单在模块里（`CONFIG_FACE_FILES` / `DOC_FACE_FILES`），其余前端源文件自动属于 creator 面。

## 技术详情层白名单

它**不是**整文件放行的特区 —— 白名单按**字符串逐条登记**在 `terminology.mjs` 的
`ADVANCED_DETAILS_ALLOWED_COPY`，守卫会检查它不能膨胀、不能留失效条目。

## 明确不做

- **不改任何标识符 / API 路径 / 错误码**（`providerId`、`/api/runs` 等保持原样）—— 界面词与协议词解耦。
- **不造译名**：`prompt` / `seed` / `蒙版` / `超分` 这类创作者语汇照留。
- **不删工程能力**：术语从创作者面「收回」，是下沉到「技术详情」层，不是删掉。

## 固化方式

只写文档守不住 —— 文案会在后续重构里被顺手改回去。所以：

1. `web/src/terminology.mjs`：单一来源，既出数据也出扫描器。
2. `tests/vnext/terminology-guard.test.js`：扫 `web/src/**` 的**可见文案**（含中文的字符串字面量与 JSX 文本，**不含注释与标识符**），命中 creator 面禁用词即 fail 并报 `文件 + 原文`。
3. **反向守卫**：本文件的条目必须与模块一一对应，防单边漂移。

已被锁住的历史约定，改前先看这里：

- 草稿阶段的边界提示只有一句 **「这一步只记草稿，不出图，也不产生费用。」**，唯一来源是 `web/src/boundary-copy.mjs`；9 个提示点全部复用它，禁止手写副本。
- 唯一讲清「确认之后会怎样」的地方是**确认出图弹窗**（`main.jsx` 的 `confirmationPlanSummary`），且**只用真实拿得到的事实**（计划里的张数 / 画幅 / 分辨率）——不编时间与金额。

## config 面与 doc 面：术语照留，但要付代价

创作者面已经清零，但**配置面与文档面刻意保留术语** —— 配置要对齐服务商文档（把 `Base URL`
翻成「网址」，用户就不知道该抄哪一栏），文档要讲清系统怎么跑。保留不是放任，代价是：

- **config 面**（`web/src/provider-settings.jsx`，人话副本在 `config-face-copy.mjs`）：
  面板顶部一句导语说清这是干什么的；**每个技术字段下方配一句人话**（`CONFIG_FIELD_HINTS`）；
  技术名词表收在**折叠区**里（`provider-glossary-panel`），与主路径视觉隔离。
- **doc 面**（创作手册，人话副本在 `doc-face-copy.mjs`）：术语在正文**首次出现处加括注**，
  例如「预检（开工前先算一遍，这一步不出图）」；顶部再挂一份**名词表**兜底，随时可查。

两份名词表都被守卫盯着：条目不能重复、人话不能为空、**每个术语必须真的在对应源码里出现过**
（不许解释一个已经不存在的词）。
