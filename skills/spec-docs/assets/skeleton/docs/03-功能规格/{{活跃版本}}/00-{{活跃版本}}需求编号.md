# {{活跃版本}} 稳定需求编号

本文档为{{活跃版本}}建立跨需求、设计、实现和测试都不随章节移动而变化的稳定编号。编号只负责追踪，不替代功能主文档中的业务细节。

## 1. 编号规则

| 类型 | 格式 | 含义 |
| --- | --- | --- |
| 功能需求 | `{{活跃版本}}-FR-NNN` | 与 `NN-中文功能名.md` 一一对应的可独立开发、测试和验收能力 |
| 非功能需求 | `{{活跃版本}}-NFR-NNN` | 跨功能的安全、性能、可靠性、可观测性或数据约束 |
| 发布门禁 | `{{活跃版本}}-RG-NNN` | 功能完成后、真实收费或扩大开放前必须满足的条件 |
| 设计分支 | `B<功能号>-NN` | 功能主文档或同名技术设计中的关键判断或副作用 |
| 功能验收 | `{{活跃版本}}-FR-NNN/ACNN` | 功能主文档“验收标准”章节中的验收条件 |
| 跨功能验收 | `{{活跃版本}}-E2E-NN` | [端到端验收规范](../../05-测试与发布/端到端验收/{{活跃版本}}-端到端验收规范.md)中的真实业务路径 |
| 性能门禁用例 | `{{活跃版本}}-RG-NNN/PERFNN` | 归属于既有发布门禁的性能与容量场景，不创建平行发布门禁 |

功能编号和 `{{活跃版本}}-FR-NNN` 永久绑定：功能改名或章节移动不得复用旧编号。

## 使用规则

1. 新增需求先在本表登记，再写入功能主文档与追踪矩阵。
2. 编号不依赖章节位置，可追踪且不复用；作废编号标注原因。
3. 跨版本延续的功能保持同一功能 ID，在功能演进矩阵中标注各版本状态。
