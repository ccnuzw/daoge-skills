## 🆕 新增工作模式

### 模式 7：增量更新文档
- **触发**：用户说"更新功能 X"、"添加 AC"
- **行为**：读取现有文档，只更新指定章节，自动记录变更
- **关键**：支持边对话边完善

### 模式 8：创建版本路线图
- **触发**：用户说"规划版本路线"、"创建路线图"
- **行为**：生成版本路线图和功能演进矩阵
- **关键**：支持 V1-V8 的整体规划

### 模式 9：规划后续版本
- **触发**：用户说"规划 V2"、"细化 V3"
- **行为**：创建版本概要文档，不细化到功能规格
- **关键**：后续版本保持概要

### 模式 10：记录开发进展
- **触发**：用户说"功能 X 已完成"、"更新进展"
- **行为**：更新功能状态，添加到实现状态文档，记录变更
- **关键**：时间倒序追踪

### 模式 11：分析文档质量
- **触发**：用户说"分析文档质量"、"检查完整性"
- **行为**：对比样例标准，生成改进建议
- **关键**：Skill 的自我完善能力

### 模式 12：对话式协作完善
- **触发**：自然对话
- **行为**：理解上下文，主动询问，给出建议
- **关键**：像真人协作一样

第五天：

### 场景 2：多版本规划

```
项目启动：
用户：规划 V1-V8 版本路线
AI：（生成版本路线图，创建 8 个版本目录）

V1 开发期：
用户：细化 V1 功能规格
AI：（在 V1 下创建详细功能文档）

V1 接近完成：
用户：规划 V2 的详细功能
AI：（提示：V1 完成度 80%，可以开始细化 V2）

```
用户：我想做一个 Agent 生命周期管理功能
AI：好的，让我们探讨细节：

    2. 如何创建 Agent？
    3. 如何启动和停止？

用户：状态有 created, running, paused, stopped
AI：明白了，我先创建初始文档...
    （生成文档）
    Agent 失败时应该怎么处理？

用户：转为 failed 状态，记录错误日志
AI：（更新状态机，添加失败处理）
